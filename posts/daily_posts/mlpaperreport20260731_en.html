Research background

Sparse Mixture of Experts (SMoE) is a parameter-efficient neural architecture that assigns different inputs to submodels called experts for efficient conditional computation. In the large-language-model era, its ability to greatly increase parameters without proportional computation has made it central to building extremely large models.

Core challenges

1. Routing stability: Deciding which expert receives each token is critical. Common token-to-expert routing develops severe late-training routing fluctuations: the same token is assigned to different experts over time, destabilizing training.

2. Load balancing: Simple greedy routing overloads some experts while underusing others, wasting capacity and increasing communication overhead.

3. Scalability limits: Distributed MoE training exchanges tokens across GPUs/TPUs; communication becomes a new scaling bottleneck.

Widely accepted settings and evaluation

Standard datasets:

  • Language modeling: WikiText-103, C4, OpenWebText
  • Downstream: GLUE/SuperGLUE (text classification), machine translation
  • Vision: ImageNet-1K, ImageNet-R (robustness variants), ImageNet-A (adversarial examples)

Common metrics: Perplexity for language modeling, accuracy for classification, and expert utilization/load-balance ratio for architectural efficiency.

Main frontier disagreements

MoE design has three main technical disagreements:

🔀 Routing paradigms

Token-Choice paradigm(traditional): Each token independently selects top-k experts. Simple, but prone to load imbalance.

Expert-Choice paradigm(Expert Choice Routing, 2022): Each expert instead selects top-k tokens, guaranteeing perfect balance but requiring global synchronization.

Graph-Based paradigm(Graph of Tokens, this week's paper): Token similarity or attention graphs guide routing, seeking a balance between the two.

⚖️ Load-balancing mechanisms

Auxiliary losses: Penalize imbalance with an extra loss, as in Switch Transformer.

Hard constraints: Guarantee balance architecturally, as in Expert Choice.

Unsupervised balancing: Exploit input distributions/structure for automatic balance, explored by this paper and recent work.

🔗 Routing strategies

Sparse routing: Each token connects to few experts.

Dense routing: Every token connects to every expert with different weights.

Dynamic routing: Adapt the expert count to input content.

Core paper deep dive

📄 Paper overview

Title: Improving Routing in Sparse Mixture of Experts with Graph of Tokens

Authors: Tam Nguyen, Ngoc N. Tran, Khai Nguyen, Richard G. Baraniuk

Publication: arXiv:2505.00792, submitted May 2025

Field: Model architecture, efficiency, sparse learning

Abstract and problem definition

The paper identifies an overlooked but serious SMoE training problem: routing fluctuations. The same token is assigned to different experts across training stages; unstable routing introduces gradient noise and harms performance.

Reexamining SMoE through probabilistic graphical models (PGMs), the authors locate the root issue in token-choice routing's independence assumption—each token's expert assignment ignores relationships and similarities with other tokens in the same example, causing instability.

Core innovation and motivation

The central insight is: Break independence by modeling inter-token dependencies to stabilize routing.

Two new routing mechanisms are proposed:

  1. Similarity-Aware Routing: Consider a token's similarity to other tokens in the same example; similar tokens tend to choose the same expert, reducing fluctuations.
  2. Attention-Aware Routing: Reuse dependencies already learned by Transformer self-attention, directly guiding expert routing with attention matrices. This is more end-to-end because attention already reflects important token relationships discovered by the model.

Narrative and argument

The paper proceeds as follows:

  1. Problem identification: Experiments show that late in standard SMoE training, approximately 30–35% of tokens are rerouted between steps. This fluctuation has been underappreciated.
  2. Root-cause analysis: The PGM framework reveals a strong, unreasonable independence assumption in token-choice routing. Real tokens are correlated semantically and positionally; ignoring these relationships induces instability.
  3. Theoretical argument: Within the PGM framework, adding similarity or attention nodes to routing decisions is shown to substantially reduce uncertain tokens' expert-selection entropy, stabilizing routing.
  4. Method design: Theory motivates concrete similarity-aware and attention-aware mechanisms, both computationally efficient and direct replacements for softmax gating.
  5. Empirical validation: Extensive language-modeling and vision experiments support theoretical predictions and show performance/robustness gains.

Methodology and technical details

Probabilistic graphical model framework

Standard token-choice routing is expressed as:

expert_assignment_i = argmax_j softmax(u_i^T W_e)_j

where u_i is token i's representation and W_e is the learnable gate-weight matrix. Each token is processed independently, ignoring others.

In PGM terms, token nodes are independent and unconnected. The key contribution adds structure:

Similarity-Aware Routing (S-MoE)

Method 1: Compute a token-similarity matrix

S[i,j] = softmax(u_i^T W_s u_j / τ)

where τ is the temperature. This matrix expresses relationships among sequence positions.

The modified gate becomes:

logits_i = u_i^T W_e + α * Σ_j S[i,j] * (u_j^T W_e)

Intuitively, a token's expert choice is influenced by similarity-neighbor tokens. Reduced routing diversity within a region stabilizes overall routing.

Attention-Aware Routing (A-MoE)

Method 2: Directly use self-attention matrices

logits_i^att = u_i^T W_e + β * Σ_h Σ_j A_h[i,j] * (u_j^T W_e)

where A_h is head h's attention matrix. Advantages include:

  1. Attention weights are already learned and reflect model-estimated token importance.
  2. No additional parameters such as S-MoE's W_s and α, reducing computation.
  3. Naturally propagates consistent routing across Transformer layers.

Implementation and hyperparameters

Key design choices:

Parameter Explanation Experimental setup
τ (temperature) Controls similarity-distribution sharpness 0.1–1.0; paper uses 0.5
α (S-MoE weight) Similarity influence on gating 0.1–0.5; paper uses 0.3
β (A-MoE weight) Attention influence on gating 0.2–0.8; paper uses 0.5
top-k Experts selected per token k=2, consistent with Switch Transformer

Important design choice: The paper states that α, β, and τ are shared across all datasets without task-specific tuning. This key claim is examined below.

Routing-fluctuation analysis

A core contribution quantifies fluctuations by tracking expert-assignment changes for the same token across training steps:

  • Baseline: Approximately 33% of tokens change experts over 100-step intervals
  • S-MoE: Reduced to ~20%
  • A-MoE: Reduced to ~18%

Expert-selection entropy also decreases substantially, indicating more decisive, consistent routing.

Value and limitations

This section provides the report's central independent critique.

1️⃣ Omitted metrics and implicit assumptions

discovery: The paper mainly reports perplexity and accuracy, omitting key efficiency metrics:

  • Computation (FLOPs): S-MoE/A-MoE add similarity/attention computation without quantifying overhead. Similarity computation is O(n²) in sequence length and may become a long-sequence bottleneck.
  • Memory usage: Storing S[i,j] requires O(n²) additional memory, substantial for long sequences.
  • End-to-end latency: Actual inference-time increases are unreported.
  • Expert utilization: Stability is discussed without detailed load-balancing analysis. Are token assignments more balanced?

Implication: ⚠️ Important. If added compute/memory outweigh gains, deployment value declines substantially.

2️⃣ Tension between tuning and “no tuning” claims

discovery: The paper claims shared α, β, τ across datasets and model sizes without tuning, an attractive proposition.

Question: Experiments show:

  • WikiText-103 uses τ=0.5, α=0.3, β=0.5
  • ImageNet-1K reportedly uses the same settings
  • Downstream tasks use the same settings

Hidden issue: How were these shared hyperparameters judged optimal? No sensitivity analysis is shown. Task-specific tuning may improve further, raising attribution questions between method and tuning gains.

Implication: ⚠️ Moderate. “No tuning” requires sensitivity evidence currently missing.

3️⃣ Insufficient isolation of gain sources

discovery: Improvements are attributed to routing stability without fully isolating it.

Challenges:

  • S-MoE adds similarity information and W_s parameters, potentially creating a stronger baseline by itself. Compare adding similarity features without changing routing.
  • A-MoE uses attention matrices computed after softmax gating, so improved routing changes attention patterns in return. Is routing itself decisive, or the resulting attention distribution?
  • No ablation separates routing-stability gains from additional information input.

Implication: ⚠️ High. This affects assessment of contribution size.

4️⃣ Efficiency curves, not single points

discovery: Results use fixed configurations: 12 layers, dimension 768, 2–8 experts.

Problem:

  • At what sequence length does S-MoE's O(n²) similarity become limiting? What is the longest tested sequence?
  • How does it scale to billions of parameters and 64+ experts?
  • As expert counts grow, how do performance–efficiency curves compare with Expert Choice Routing?

Implication: ⚠️ Moderate. Applicability to very large models remains unclear.

5️⃣ Failure modes and edge cases

discovery: Only successful cases are shown.

Missing analyses:

  • Under which inputs does improved routing fail or worsen performance?
  • For 1–2-token sequences, similarity provides little information; how does the method degrade?
  • Is it robust to highly uneven tokens, all-padding inputs, or heterogeneous sequence-length distributions?
  • Word-swap attacks are mild; what about stronger attacks such as token deletion?

Implication: ⚠️ Moderate. Production edge cases lack discussion.

6️⃣ Do conclusions exceed evidence?

Paper claim: “By modeling token dependencies, we provide a general, efficient, tuning-free method for stabilizing MoE routing.”

Evidence coverage:

  • ✓ Language modeling (1 dataset)
  • ✓ Image classification (1 main dataset + 2 robustness variants)
  • ✓ Downstream NLP (3 small datasets)
  • ✗ Other MoE applications such as multimodal tasks, retrieval, recommendation
  • ✗ Specific tasks such as code generation and translation

Generality rests on limited coverage; efficiency is also insufficiently established (point 1).

Implication: ⚠️ Low to moderate. Overstatement is common, although experiments are reasonably comprehensive within covered areas.

7️⃣ Reproducibility and code availability

discovery: Hyperparameters and datasets are detailed, but code/pretrained-weight availability at the May 2025 arXiv release is unknown.

Evaluation:

  • Numbers and configurations enable reproduction from scratch, a positive feature.
  • Without official implementation, multitask computation requirements would reduce adoption substantially.
  • Similarity-matrix implementation details, including approximation/further optimization, are insufficient.

Implication: ⚠️ Low. Scientific contribution does not require released code, but industrial adoption suffers.

Overall value assessment

✅ Lasting core contribution

The probabilistic graphical model perspective is the most valuable element. Reinterpreting routing stability through graph models supplies a new theoretical framework for routing design, likely relevant for 5–10 years.

⚡ Engineering gains versus foundational innovation

Concrete S-MoE/A-MoE methods may mainly offer engineering gains. An 8% perplexity improvement is meaningful in LLM competition, but comes from extra information rather than a fundamental breakthrough. Changing to Expert Choice Routing or adding other stabilization could shrink that relative gain.

❌ What this paper is not

This paper is not a fundamental MoE architectural breakthrough, and is not a ready-made solution for arbitrary large systems, given unresolved efficiency. It is an incremental improvement demonstrating stability and performance gains at particular scales/tasks.

Related work and technical lineage

This chapter traces MoE routing to locate Graph of Tokens within the field.

Stage 1: Basic sparse MoE and Token-Choice Routing (2017–2021)

Switch Transformer (Fedus et al., 2101.03961, JMLR 2022)

Key Innovations: Simplifies routing to one expert per token (K=1), adding auxiliary load-balancing loss.

Exposed problem: Despite auxiliary loss, token-choice routing still produces imbalance, capacity shortages, and dropped tokens. Routing depends entirely on each current token without context.

Unresolved issues: Imbalance worsens with larger models and longer sequences.

GLaM (Du et al., 2112.06905, ICML 2022)

Key Innovations: Demonstrates efficient MoE training on Google's infrastructure with 64 experts and 1.2T parameters.

Contribution scope: Primarily systems/engineering—communication optimization and batch scheduling—rather than algorithmic innovation.

Unresolved issues: Routing remains token-choice + auxiliary loss, without resolving stability fundamentally.

Stage 2: Expert-Choice and reverse routing (2022–2024)

Mixture-of-Experts with Expert Choice Routing (Zhou et al., NeurIPS 2022, 2202.09368)

Key Innovations: Reverse routing lets each expert select top-k tokens. Algorithmically guaranteed uniform assignment resolves load imbalance.

Benefit:

  • Eliminates imbalance: ideal uniformity versus token-choice's 30–40% imbalance
  • Allows heterogeneous expert counts per token, improving expressivity
  • 2× training speed from balanced loads and fewer synchronization barriers

Remaining problems: Global synchronization still costs communication in distributed settings. Inference latency requiring global softmax may be less flexible than token choice.

Auxiliary-Loss-Free Load Balancing (2408.15664, 2024)

Key Innovations: Proposes auxiliary-loss-free balancing by modifying gates to encourage uniform allocation directly.

vs Expert-Choice: Seeks Expert-Choice-like balance within token choice at lower computational cost.

Unresolved issues: Routing fluctuations remain unaddressed directly.

Stage 3: Routing stability and structured routing (2024–2026)

Load Balancing MoE with Similarity Preserving Routers (2506.14038, 2025)

Key Innovations: Preserves inter-token similarity structure to guide routing; similar tokens should receive similar expert combinations.

vs Graph of Tokens: Related idea, different implementation: explicit similarity constraints rather than Graph of Tokens' graphical-model framework.

Complementarity: Near-contemporaneous papers converge on token similarity for stable routing.

Routers Learn the Geometry of Their Experts (2605.12476, 2025)

Key Innovations: Geometrically analyzes routers and experts, showing routers implicitly learn expert clustering in representation space.

Implication: Supports Graph of Tokens' intuition that token–expert relations are structured, not independent.

Improving Routing with Graph of Tokens (2505.00792, this paper)

Key Innovations: Unifies these ideas through PGMs and proposes two concrete solutions.

Position: At the intersection of this lineage, inheriting Expert Choice's emphasis on balance and similarity-preserving/geometric insights.

Technical-lineage summary

Evolution:

Token-Choice + Auxiliary Loss (2021) → Expert-Choice perfect balance (2022) → Balance/stability within Token-Choice (2024) → Graphical models and structured routing (2025–2026)

Evolution of the core problem:

  1. Load imbalance (2021–2022): Essentially addressed by Expert Choice
  2. Routing stability (2024–present): Newer, subtler, important focus
  3. Computational efficiency (throughout): Persistent tradeoff—Expert Choice synchronization versus Token Choice imbalance

Graph of Tokens' position: Provides a unified theoretical framework and two practical solutions for emerging routing-stability research. Its value is connecting scattered similarity/attention observations through PGMs rather than pursuing novelty alone.

Next directions and open questions

Promising directions based on this paper and related work, ranked by expected benefit / difficulty:

🥇 High benefit, moderate difficulty

1. Optimize S-MoE for long sequences

Problem: O(n²) similarity becomes a bottleneck when n > 4096.

Direction: Approximate S[i,j] using local windows, random sampling, or hierarchical clustering, retaining stability gains at lower cost.

Implication: Preserving over 90% of the effect in O(n log n) or O(n) would greatly improve practicality.

Difficulty: Moderate; requires careful approximation and extensive experiments.

2. Hybrid with Expert Choice

Problem: Graph of Tokens provides stability; Expert Choice guarantees balance. They complement one another.

Direction: Use Expert Choice in some layers for balance and graph routing in others for stability, or explicitly trade between them.

Implication: Could match the best of both or surpass either alone.

Difficulty: Moderate; needs new architecture and added training-cost analysis.

🥈 High benefit, high difficulty

3. Dynamic routing policies

Problem: Current methods assume a fixed count (fixed k), though tokens may need different expert counts.

Direction: Dynamically choose experts per token based on uncertainty/complexity; graphical models naturally express this decision.

Benefit: Potential efficiency gains from fewer experts for simple tokens, more for complex ones.

Difficulty: High; requires differentiable gating for expert counts.

4. Consistent cross-layer and cross-task routing

Problem: Independent per-layer routing can assign completely different experts to a token, wasting higher-level caching/optimization opportunities.

Direction: Introduce global graph constraints encouraging consistent cross-layer choices while allowing necessary changes.

Benefit: Better cache locality and inference throughput.

Difficulty: High; global cross-layer optimization increases training costs substantially.

🥉 Moderate benefit, low difficulty

5. Multitask and multilingual evaluation

Problem: Evaluation focuses on English and single-task settings.

Direction: Test translation, multilingual classification, and multitask learning to verify tuning-free hyperparameters.

Difficulty: Low; mainly additional experiments.

Benefit: Demonstrating no tuning across languages/tasks would be a meaningful empirical contribution.

6. Inference optimization: Expert-Aware Batching

Problem: Different expert combinations across batches can undermine GPU expert parallelism.

Direction: Schedule requests with matching expert combinations together to maximize parallel utilization; Graph of Tokens' routing consistency could make this especially effective.

Difficulty: Low to moderate; requires inference-engine support.
