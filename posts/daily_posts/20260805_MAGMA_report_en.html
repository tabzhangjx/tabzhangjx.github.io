2. In-Depth Analysis of the Core Paper

2.1 Abstract and Positioning

The paper's specific claim, rather than a generic summary: existing Memory-Augmented Generation (MAG) systems store memory in one monolithic repository indexed solely by semantic similarity, entangling temporal, causal, and entity information. MAGMA places each memory entry simultaneously in four orthogonal semantic, temporal, causal, and entity graphs and formalizes retrieval as policy-guided traversal over these relational views.

Core innovation in one sentence: Retrieval becomes identifying the relation a question asks about and following edges of that type, instead of finding nearest neighbors in one vector space.

The significance is that it moves the memory bottleneck from what to store to which relations to store it under. Nemori asks what deserves retention, MemoryOS asks how long and in which tier, and A-MEM asks whether memories should be linked. MAGMA asks which kind of edge to create and which kind to follow at query time.

2.2 Motivation and Problem Evidence

Specific problems (§1): ① Distance-related attention degradation, or lost-in-the-middle, prevents longer context alone from solving long-term memory. ② A single semantic index loses relational structure; A-MEM-style similarity retrieval misses temporal and causal relations. ③ Object permanence breaks when the same entity appears across interrupted timeline fragments: semantic retrieval cannot join them into one object, directly motivating the entity graph.

How Are These Problems Quantified? The paper no provide separate diagnostic experiments quantifying the three problems; instead it uses an indirect argument: Full context (101K tokens) reaches only 55.0% on LongMemEval, whereas structured retrieval with 3.4K reaches 61.2%, demonstrating that longer context does not imply better memory.

However, case studies (Table 8 / §E.2) provide three verifiable qualitative examples:

What Is Novel: Novelty lies beyond using graphs, as GraphRAG and Zep already do, in refusing to collapse semantically different relations into one graph. Zep encodes time as edge attributes; GraphRAG places entities and communities at two levels of one graph; A-MEM uses homogeneous links. MAGMA bets that decoupling relation types itself helps because retrieval policies gain explicit choices.

2.3 The Paper's Argument

The paper follows a clear chain of reasoning:

Observation A: Longer context makes attention less reliable (lost-in-the-middle). ↓ Expanding the window is insufficient. Observation B: External memory requires retrieval, currently dominated by semantic similarity. ↓ Relations not expressible as similarity are lost. Inference C: Time (A before B), causality (A causes B), and coreference (A and B are one person) are not semantic similarity. ↓ ★ Critical transition Hypothesis D: Represent these relations as separate edge sets; retrieval becomes choosing which edge type to follow rather than nearest neighbors. ↓ Representation learning becomes policy selection. Method E: Classify query intent (Why / When / Entity) → edge-type weights w_{T_q} → beam-search traversal → linearize the graph into a prompt. ↓ LLM causal inference on every write is too slow. Engineering F: Dual streams: a fast path builds temporal chains and vector indexes; an asynchronous slow path adds LLM-inferred causal/semantic structure.
The critical step is C→D. The paper's falsifiability rests here: if sufficiently good embeddings already encode temporal, causal, and entity relations implicitly, four graphs add only engineering complexity. Table 5's single-graph ablations respond, but incompletely (see §2.7 B2).

2.4 Methodology and Mechanisms

2.4.1 Data Structures

G_t = (N_t , E_t) Time-varying directed multigraph n_i = ⟨ c_i , τ_i , v_i , A_i ⟩ Unified Event-Node c_i ∈ Text Event content (observation / action / state change) τ_i ∈ ℕ Discrete timestamp v_i ∈ ℝ^d Dense vector (stored in vector database; default d = 384) A_i Structured metadata (entities, temporal cues, context descriptors)

2.4.2 Four Relation Graphs (§3.1)

GraphEdge-set definitionDecision mechanismSpecific failure addressed
Temporal EtempStrictly ordered pair (n_i, n_j), τ_i < τ_jRule-based, created immediately at write time in O(1)Failure to normalize “yesterday” to an absolute date
Causal EcausalDirected edge, S(n_j|n_i, q) > δAsynchronous LLM inference on the slow path, with confidenceInability to trace effects back to causes in “why” questions

An Important Asymmetry. Of the four graphs, only the semantic graph already exists in conventional methods, yet Tables 4/5 ablate only the other three. §2.7 B2 develops this into a substantive criticism.

2.4.3 Query Pipeline: Adaptive Hierarchical Retrieval (Algorithm 1, Four Stages)

Stage 1 — Query Analysis and Decomposition: Intent classification T_q ∈ {Why, When, Entity}; temporal parsing (relative expressions → absolute interval [τ_s, τ_e]); representation extraction (dense q⃗ + sparse keywords q_key).

Stage 2 — Multisignal Anchor Identification (Reciprocal Rank Fusion):

S_anchor = Top_K ( Σ_{m ∈ {vec, key, time}} 1 / ( k + r_m(n) ) )

Stage 3 — Adaptive Traversal Policy (Heuristic Beam Search), with transition scoring combining structural alignment and semantic affinity:

S(n_j | n_i , q) = exp( λ₁ · φ( type(e_ij) , T_q ) + λ₂ · sim( n⃗_j , q⃗ ) ) Structural alignment: φ(r , T_q) = w_{T_q}ᵀ · 𝟙_r

Thus, the edge-type weight vector w is a function of intent T_q: Why questions increase causal weights, When questions increase temporal weights. Each step keeps the top-k nodes, with depth decay γ.

Stage 4 — Narrative Synthesis Through Graph Linearization:

C_prompt = ⊕_{n_i ∈ Sort(G_sub)} [ <t:τ_i> n_i.content <ref:n_i.id> ] Ordering: Temporal queries sort by τ; causal queries topologically sort E_causal (causes before effects). Budget: Preserve full text for highly relevant nodes; compress low-probability nodes into shorthand (salience-based budgeting).

2.4.4 Dual-Stream Memory Evolution

Incoming event I │ ├─── Fast path (Algorithm 2 · latency-sensitive · nonblocking · no LLM) │ ① n_t ← SegmentEvent(I) │ ② G.AddEdge(n_prev, n_t, type=Temp) ← Immediate temporal skeleton │ ③ v_t ← Encoder(n_t.c) ; VDB.Add(v_t, n_t.id) │ ④ Queue.Enqueue(n_t.id) │ └─── Slow path (Algorithm 3 · asynchronous · LLM-intensive) ⑤ Dequeue recent events and densify graph structure ⑥ E_new = Φ_reason( N(n_t) , H_history ) ← Infer latent causal/semantic edges ⑦ Update causal confidence; merge redundant semantic clusters
This is the most independently reusable engineering design in the paper. It separates immediate work—temporal chains and vector indexes using rules or encoders—from deferrable LLM work—causal inference and semantic clustering—at the critical-path level. MemoryOS's 32.68s query latency (Table 3) likely reflects the cost of lacking this separation.

4. Value and Limitations

4.1 Assessment of Value

The Substantive Contribution. MAGMA reframes agent-memory retrieval from a metric-learning problem(embedding queries and memories in one space) into a policy problem(choosing among relations with known semantics). The value is that retrieval becomes interpretable, controllable, and composable. Failed vector retrieval mainly prompts embedding changes; failed relational traversal can be localized to missing causal edges or incorrect intent classification.

Four Independently Reusable Designs

  1. Dual-stream writing (fast/slow path separation)—independent of four-graph decomposition. Any memory system requiring LLM structural inference on writes can synchronously build rule-based skeletons and asynchronously infer richer relations. MemoryOS's 32.68s illustrates the alternative.
  2. Intent-to-edge-weight routing (φ(r, T_q) = w_{T_q}ᵀ·𝟙_r)—usable whenever memory has multiple edge types, regardless of their semantics. It has the largest individual ablation contribution (−0.063).
  3. Topologically ordered context linearization—place causes before effects in causal-query prompts. Almost free and orthogonal to retrieval design.
  4. <ref:id> Provenance labeling—a plausible mechanism behind the adversarial jump from 0.325 to 0.742, letting the model see its lack of evidence.

Implications for Future Work. Replacing φ, currently a handcrafted weight table, with a learned policy is the most direct next step. Currently, w_{T_q} is manually set (entity 2.5–6.0 / temporal 0.5–4.0 / causal 3.0–5.0), with only three intent categories. This is precisely where MemRL / Memory-R1's RL line can connect: MAGMA supplies the action space; RL supplies the learning signal.

4.2 Limitations A: Acknowledged by the Paper (§6)

  1. Dependence on LLM Reasoning Fidelity. Graph quality depends on the LLMs used for asynchronous consolidation. Erroneous or missing relations can propagate into retrieval; structured prompts and conservative thresholds only mitigate this risk.
  2. Storage and Engineering Complexity from Multiple Graphs. Multiple relational views and dual-stream processing add implementation and memory overhead, limiting suitability in constrained environments.
  3. Narrow Evaluation. The authors acknowledge that most agent-memory systems, including theirs, are evaluated only on long-context dialogue benchmarks such as LoCoMo and LongMemEval, excluding multimodal and heterogeneous observation streams.

4.3 Limitations B: Independent Criticisms

B1 · Argument Gap: The Core Claim Conflicts with the Data (Most Serious)

The paper claims consistent superiority on long-horizon reasoning. Yet the §3.2 decomposition attributes 98.98% of the overall advantage over Nemori to adversarial abstention. On the remaining 1,540 examples, MAGMA scores 0.6882 versus 0.6869, a difference of +0.13pp. Multi-hop directly contradicts consistency (0.528 vs 0.569, −7.2%). A more accurate claim is substantially improved abstention calibration and much lower latency at comparable reasoning accuracy.

B2 · Experimental Design: Four Graphs Claimed, Only Three Ablated

The paper repeatedly emphasizes four orthogonal semantic/temporal/causal/entity graphs, but Table 4 removes only causal, temporal, and entity graphs: there is no w/o Semantic. Table 5 likewise has only Causal Only, Temporal Only, and Entity Only: there is no Semantic Only. Semantic Only is precisely the null hypothesis: approximately vector RAG with beam search. Without it, the core claim that relational decoupling helps is never tested against its own null. This is the essential missing cell.

B3 · Experimental Design: Promised Hyperparameter Study Supplies Only Ranges

Appendix B lists λ₂ ∈ [0.3, 0.7], θsim=0.75, δ=0.6, beam=8, and γ=0.85, describing empirical optimization on LoCoMo, but provides no sensitivity curves or sweep tables. Thus (i) the share of the 0.700 score attributable to benchmark tuning is unknown (θsim and δ control graph density and have high leverage), and (ii) transfer retuning costs are unknown. This materially limits a system centered on threshold-based graph construction.

B4 · Metric Validity: Two Overall Rows Cannot Be Reconstructed

As §3.3 shows, MAGMA/A-MEM/MemoryOS reconcile from category scores (|Δ|<0.0005), but Nemori (Δ=+0.0157) and Full Context (Δ=+0.0126) do not. Correcting Nemori lowers the lead from +18.6% to +15.6%. Those rows are also the likeliest external quotations, suggesting mixed evaluation protocols.

B5 · Terminology Exceeds the Evidence: “Orthogonal” Is Overloaded

The LOO-drop sum of 0.206 is 1.87 times the full-versus-best-single gap of 0.110 (§3.6). Genuine independence would make them close; 1.87× suggests strong functional coupling. Orthogonal means only disjoint edge sets at the representation level, while the prose implies decomposable contributions at the effect level. This could mislead subsequent modular pruning efforts into expecting much stronger results than they obtain.

B6 · Missing Key Comparisons: No Graph-Structured Baseline

Table 1 uses Full Context, A-MEM, MemoryOS, and Nemori, with no graph-memory baseline, despite discussing GraphRAG and Zep. Zep reports up to +18.5% LongMemEval accuracy and −90% latency. A claim that multiple graphs are needed requires at least one single-graph baseline such as Zep or GraphRAG to isolate the difference. Current comparisons establish structured > unstructured, not multiple graphs > one graph—the actual contribution claim.

B7 · A Failing Subtask and a Structural Explanation

MAGMA's 0.528 on multi-hop trails Nemori's 0.569 by 4.1pp (−7.2%). This is counterintuitive because multi-graph traversal should excel at multiple hops. A testable hypothesis is premature pruning with beam width 8 and maximum depth 4–5. Table 5's multi-hop scores—Causal Only 0.470, Entity Only 0.485, full 0.528—suggest strong dependence on cross-graph combinations, whose candidates may be lost during layerwise pruning. The paper does not discuss this. Nemori instead pre-encodes cross-event relations in narrative compression, avoiding traversal pruning.

B8 · What If Abstention and Reasoning Were Evaluated Separately?

LoCoMo makes 22.5% of examples unanswerable, then combines correct answers and correct refusals into one LLM-judge Overall. This aggregation favors conservative abstention: always refusing earns perfect adversarial performance and 0.225 Overall. Future work should report two separate numbers: non-adversarial accuracy for capability and adversarial abstention for calibration, analogous to precision/recall. Under this protocol, MAGMA's story becomes equal capability and much better calibration—a more informative conclusion.

B9 · Limitations of This Analysis

  • I cannot prove that Table 1 Overall is a sample-weighted micro-average. Exact reconstruction of three rows is strong evidence, not proof.

5. Related Work: Making Memory Structure Increasingly Explicit

These works trace how one problem is progressively unpacked: pageable text → linked notes → a hierarchical lifecycle → a temporal knowledge graph → selected narratives → MAGMA's relation-separated, intent-routed graphs.

5.1 GraphRAG (Edge et al., arXiv 2404.16130, v1 2024-04, v2 2025-02)

Problem addressed. Naive RAG locates passages mentioning an entity but struggles with corpus-wide synthesis. GraphRAG uses LLMs to build entity graphs and precompute community summaries, then generates local answers from those summaries and merges them. In one sentence: the retrieval unit moves from chunks to graph communities.

Unresolved problem. GraphRAG is a static corpus index designed for one-time construction and repeated queries. It lacks incremental writes, temporal validity, and distinct relation types, using broadly co-occurrence or association edges. All three limit agents with continuous interaction and changing facts.

MAGMA's Response. It inherits LLM structure extraction in the slow path's Φ_reason but changes it from offline batch processing to online asynchronous streaming and splits one edge type into four. Community summaries correspond to MAGMA's salience-based budgeting.

Transfer of key designs. The LLM-as-graph-builder paradigm carries over, while precomputed summaries become intent-driven query-time traversal—a shift from precomputation to on-demand routing.

5.2 MemGPT (Packer et al., 2023; Cited by MAGMA as ACL 2023 Companion)

Problem addressed. Introduces the operating-system virtual-memory metaphor: main context is physical memory, external storage is disk, and the LLM pages between them through function calls. In one sentence: let the model manage what belongs in context.

Unresolved problem. Paging operates on unstructured text blocks. MemGPT solves capacity but not relations among stored items. Retrieval still relies on similarity, and decisions depend on brittle, nonlearnable prompt heuristics.

MAGMA's Response. Yes Integration Rather Than Opposition: Keep persistent external storage and on-demand loading, but replace unstructured blocks with events bearing four relations, and prompt-based loading decisions with intent classification plus weighted traversal.

Transfer of key designs. The nonblocking fast path and asynchronous slow path recut MemGPT's foreground interaction/background memory management along latency boundaries.

5.3 A-MEM (Xu et al., NeurIPS 2025 main conference, arXiv 2502.12110)

Problem addressed. Inspired by Zettelkasten, memories grow their own network: New memories become structured notes with contextual descriptions, keywords, and tags; the system links them to historical memories, and new entries trigger updates to older representations through memory evolution. The original critique is that basic storage/retrieval lacks sophisticated organization, while fixed operations and structures restrict adaptability. In one sentence: memories should be linked, with both links and content evolving.

Unresolved problem. A-MEM's links are homogeneous: every edge indicates semantic relatedness, still based on embedding similarity. Temporal and causal relations must remain implicit; retrieval remains vector search, with links expanding rather than guiding recall. Table 1 reflects this: A-MEM scores only 0.474 on LoCoMo Temporal, second lowest.

MAGMA's Response. This is Direct Challenge: MAGMA's premise is that homogeneous A-MEM-style links are insufficient. It splits one edge type into four and incorporates type into φ(type(e_ij), T_q). Temporal rises from 0.474 to 0.650 (+37.1%, calculated here).

Transfer of key designs. Generating structured metadata A_i—entities, temporal cues, and context descriptors—at write time directly inherits A-MEM's note format. Memory evolution becomes slow-path confidence updates for causal edges and merging of redundant semantic clusters.

5.4 MemoryOS (Kang et al., EMNLP 2025 Main, Oral, arXiv 2506.06326)

Problem addressed. Organizes memory by lifecycle: short-, mid-, and long-term personal storage with four operators—store, update, retrieve, generate. On LoCoMo with GPT-4o-mini, it reports relative F1 +48.36% and BLEU-1 +46.18%. In one sentence: memory needs explicit hierarchical management and paging policies, beyond a repository.

Unresolved problem. Its hierarchy follows recency and heat rather than relation type: where memories belong and when they are promoted or evicted, rather than how they relate. Serializing four operators synchronously is expensive: Table 3 gives query latency of 32.68 s, which is 22.2 times MAGMA's (calculated here), making interactive use impractical.

MAGMA's Response. Under along two orthogonal axes: Four graphs supply the missing relation axis, while dual streams move expensive operators off the critical path, reducing latency to 1.47s. MemoryOS remains the strongest Open-Domain baseline at 0.504, only 2.6% behind MAGMA, suggesting independent value from hierarchical management.

Transfer of key designs. The principle that different memory operations deserve different treatment remains, but classification changes from temporal tiers to synchronicity through fast/slow paths—a clean repartitioning.

5.5 Zep / Graphiti (Rasmussen et al., arXiv 2501.13956, v1 2025-01-20)

Problem addressed. The first agent-memory system making temporal validity a first-class concept: Graphiti maintains both event time and record time, representing facts that were once true but later superseded. Reported results include DMR 94.8% versus MemGPT 93.4%, up to +18.5% LongMemEval accuracy, and up to 90% lower latency. In one sentence: facts in agent memory have lifetimes, and graphs must represent expiration.

Unresolved problem. Zep makes only A dimension—time—explicit, leaving causality and coreference in shared edge and node attributes. More importantly, retrieval does not change its traversal by question type: It is a smarter graph with a fixed retrieval pipeline.

MAGMA's Response. MAGMA generalizes first-class time into first-class relations, each with its own graph, then adds a layer missing from Zep: query intent determines which graph to traverse. MAGMA can thus be viewed as expanding Zep across dimensions and adding routing.

Transfer of key designs. The temporal skeleton E_temp, an immutable chain strictly ordered by τ, simplifies Zep's timeline. Relative-expression normalization into [τ_s, τ_e] likewise parallels Zep.

An Essential Missing Comparison. As B6 notes, MAGMA does not include Zep as a baseline. This is particularly unfortunate: Zep best represents a single time-aware graph, the natural control for the multiple-versus-single-graph claim.

5.6 Nemori (Ma, Nan, Wu, Chen; arXiv 2508.03341, v1 August 2025, Retitled in v4 April 2026)

Problem addressed. Addresses what deserves retention, previously handled by designer heuristics, using prediction error as value: predictable interactions need not be stored; failed predictions indicate new knowledge. Its two components turn interactions into structured narratives and extract insights by predictability. In one sentence: write thresholds should depend on surprise rather than manual rules.

Unresolved problem. Nemori concentrates on content selection, after which organization remains structured narrative text and retrieval returns to semantic matching. One concrete failure is Table 1's adversarial score of 0.325, lowest except Full Context. A plausible explanation is that coherent distilled narratives nearly always offer something apparently relevant, encouraging answers despite missing evidence—high-quality compression weakens the visibility of insufficient evidence.

MAGMA's Response. This is the source of §3.2's 98.98%. MAGMA's structured subgraphs and <ref:id> provenance make failure to find evidence a decidable structural fact, such as exhausting causal traversal depth without a relevant node, instead of an ambiguous low similarity. Adversarial rises from 0.325 to 0.742 (+128%, calculated here).

Yet This Is Also Where MAGMA Falls Short. Nemori's narrative compression still leads on multi-hop (0.569 vs 0.528): pre-encoding cross-event relations is more reliable than query-time beam-search assembly.

Transfer of key designs. Nemori is MAGMA's main comparator rather than a technical source. They form a clean contrast: write-time compression (Nemori) versus query-time assembly (MAGMA)—itself a valuable next experiment.

7. Open Challenges and Research Opportunities

7.1 Theory

7.1.1 Relational Orthogonality Needs a Measurable Definition (High Value, Low Barrier)

§3.6's LOO sum is 1.87× the full-versus-best-single gap, indicating functional coupling, while orthogonality currently means only disjoint edges. Concrete proposal: Use variance decomposition to separate main effects and pairwise interactions across all 2⁴=16 graph subsets on LoCoMo. Construction is needed only once, keeping cost manageable. The resulting interaction matrix would identify redundant and complementary graph pairs—an experiment absent from the field.

7.1.2 Separate Abstention and Capability at the Metric Level (High Value, Low Barrier)

LoCoMo aggregates 22.5% unanswerable and 77.5% answerable examples into one score, allowing a wholly conservative system 0.225 for free. Concrete proposal: Report (Acc_answerable, AbstentionRate_unanswerable) as a pair, then sweep the abstention threshold to plot their trade-off. No new data are needed, only different reporting, but existing rankings could change, as §3.2 illustrates.

7.1.3 Formalizing Write-Time Compression vs Query-Time Assembly

Nemori and MAGMA form a clean contrast. Information-theoretically, the question is where to pay the distortion cost: compression fixes distortion irreversibly at writing; query-time assembly defers it but adds traversal cost. What to Keep, What to Forget has begun applying rate–distortion theory to memory compression, but the timing of compression remains unmodeled. Concrete proposal: Derive distortion lower bounds under a fixed token budget and predict the query distributions at which the strategies cross over.

7.2 Engineering and Applications

7.2.1 Add the Missing Semantic-Only and Zep Baselines (Decisive, Very Low Barrier)

This report considers it the most urgent gap. The multiple-graph superiority claim lacks both its own Semantic-Only null and external single-graph representatives such as Zep/GraphRAG. Concrete proposal: Under In the open-source repository, disable three graphs for Semantic Only and add a Graphiti baseline with identical judge and backbone. This modest experiment could decide the core claim. Until then, multiple graphs > one graph remains unverified.

7.2.2 Report Total Slow-Path Compute, Not Just Query Latency

§3.7 shows that dual streams systematically favor MAGMA in latency and query-token columns. Concrete proposal: All asynchronously consolidated memory systems should report the (query latency, query tokens, background LLM calls per stored event, background tokens per stored event) four-tuple, restoring comparability to low-latency claims.

7.2.3 Investigate Multi-Hop Pruning Failures Directly

MAGMA trails Nemori by 7.2% on multi-hop, supposedly the strength of multiple graphs. Concrete proposal: Sweep beam width × depth (4/8/16 × 3/4/5/6), examining only multi-hop. Unsaturated monotonic improvement supports pruning as the cause, fixable with compute. Otherwise the problem lies in the score's φ interval's cross-graph comparability, with edge types on unnormalized scales—a more substantive modeling defect.

7.2.4 Dynamic Use and Graph Aging

MAGMA's graph grows; slow-path merging removes semantic redundancy, but there is no forgetting or downweighting mechanism. Over months, causal edges may accumulate LLM extraction errors. SSGM already argues that evolving-memory errors accumulate and persist. Concrete proposal: Update causal confidence using later retrieval utility: increase it when retrieved evidence yields correct answers, decrease it after errors. This is a gradient-free precursor to §7.3.1's learned policy.

7.3 Emerging Directions

7.3.1 Learned Traversal Policies (The Most Direct Next Step)

In φ(r, T_q) = w_{T_q}ᵀ·𝟙_r, w could become an RL-learned policy rather than manual settings, while intent moves from {Why, When, Entity} three classes to a continuous representation. MAGMA supplies the action space, and the MemRL line supplies the learning signal. Concrete proposal: Use traversal trajectories as episodes and final-answer judge scores as GRPO rewards—Supersede already raises small-model memory updating from 9.0% to 16.7% with GRPO, demonstrating trainability of memory-operation policies.

7.3.2 Reversible Relational Compression

Salience-based budgeting compresses less relevant nodes into shorthand, irreversibly: mistaken compression cannot be undone. R³Mem is exploring reversible compression. Concrete proposal: Make shorthand expandable during traversal when a branch becomes important, allowing retrieval of original text and revocable compression decisions.

7.3.3 Multiple Views and Multimodality

Four graphs naturally extend to multimodal settings: visual observations carry timestamps and entities but lack directly comparable semantic embeddings. Relative graph importance should therefore change sharply, with stronger temporal/entity weights—exactly where learned weights may beat handcrafted ones.

7.3.4 Security of Relational Graphs

Four graphs create four attack surfaces. Causal edges inferred asynchronously by an LLM receive no human or rule-based verification, making them especially vulnerable: a fabricated causal edge can redirect Why queries toward attacker-chosen nodes. SSGM 's four-dimensional failure taxonomy—Stability, Validity, Efficiency, Safety—offers a framework, but no concrete attack-surface analysis yet targets multi-graph memory. Concrete proposal: Build a causal-edge-poisoning benchmark measuring Why-query hijacking after injection of k fabricated edges.

9. Other Recent Work Worth Following

MemEvolve: Meta-Evolution of Agent Memory Systems (2025-12, ICML 2026)

Optimizes not memory content but the memory system's architecture: EvolveLab decomposes 12 representative systems into encode/store/retrieve/manage modules, then uses agent meta-evolution to adapt architectures, improving SmolAgent/Flash-Searcher by up to 17.06%. If learned policies are next (§7.3.1), this is a comprehensive precursor.
arXiv | Code

MemRL: Self-Evolving Agents via Runtime Reinforcement Learning on Episodic Memory (2026-01, arXiv)

Uses RL for runtime evolution of episodic memory without weight updates. Two-stage retrieval filters noise then identifies useful strategies, surpassing SOTA on HLE, BigCodeBench, ALFWorld, and LifelongAgentBench. It provides a ready technical foundation for learning MAGMA traversal.
arXiv | Code

Supersede: Diagnosing and Training the Memory-Update Gap in LLM Agents (2026-06, arXiv)

Treats failure to retain updated facts as an isolated, measurable gap: LongMemEval knowledge-update falls from 92% with full context to 77% with bounded self-maintained memory (gpt-5.4, p=0.0033), and larger memory does not restore performance(28%→28%), indicating a policy rather than capacity issue. GRPO fine-tuning Qwen2.5-3B raises held-out accuracy from 9.0% to 16.7%. A particularly clean demonstration that memory operations are trainable, directly supporting §7.3.1.
arXiv

How Memory Management Impacts LLM Agents: An Empirical Study of Experience-Following Behavior (2026-07, ACL 2026 Main Conference, Long Paper)

Identifies experience following: more similarity between retrieved memory and current input produces more similar outputs. This yields error propagation and mismatched experience replay; using future task outcomes as retrospective quality labels for stored experience improves long-term performance. Complementary to MAGMA: how to retrieve versus the quality of retrieved material.
ACL Anthology

H-MEM: Hierarchical Memory for High-Efficiency Long-Term Reasoning in LLM Agents (2026-03, EACL 2026 Long)

Using semantic abstraction level organizes memory hierarchically; higher-level vectors encode positional indexes to lower-level memories, enabling layerwise routing without exhaustive similarity computation. A contemporary alternative in structured retrieval: MAGMA organizes horizontally by relation, H-MEM vertically by abstraction. In principle, they combine.
ACL Anthology

From Recall to Forgetting: Benchmarking Long-Term Memory for Personalized Agents (Memora) (2026-04, arXiv)

A benchmark spanning weeks of conversations, including consolidation and mutation, with FAMA metrics that penalize reliance on outdated information. Memory agents achieve aggregate FAMA 119.45 for remembering versus LLMs' 65.60–65.80, but only 27.55 for reasoning versus 12.37–13.92—remembering is easier than reasoning, consistent with this report's §3.2 finding.
arXiv

ForgetBench: Benchmarking Forgetting Dynamics of Long-Term Parametric Memory (2026-07, arXiv)

On the parametric-memory side, this work evaluates retention under sequential knowledge edits. AlphaEdit reaches 0.92 editing success on Qwen-2.5 7B but has a memory half-life of only 452 steps; stability-oriented WISE succeeds below 0.12. The retention-versus-effectiveness trade-off parallels compression versus decidability in external memory.

Governing Evolving Memory in LLM Agents: the SSGM Framework (2026-03, arXiv)

Memory governance and security: a four-dimensional Stability / Validity / Efficiency / Safety taxonomy argues for decoupling memory evolution from execution, adding validation gates and temporal decay. The claim that evolving-memory errors accumulate and persist directly targets MAGMA's unguarded slow-path causal inference (§7.3.4).
