HPS：把“最难负例”变成偏好对齐的采样分布

Hard Preference Sampling 的理论、证据与安全含义

ICML 2025 / PMLR 267 2026-09-21 偏好优化 · 对齐 · 负例采样

HPS 用外部排序器从多负例中抽一个“最像正例”的负例，在几乎不损害外部质量分的同时显著拉大隐式奖励间隔并节省训练时间；但 margin 指标与目标函数高度同构，安全结论仍需独立红队与单样本部署评测闭环。

一句话核心定位。 HPS（Hard Preference Sampling）不是新的 DPO 替代品，而是一层可插拔的多负例采样机制：先用外部标量奖励把 99 个拒绝答案变成随训练逐步变尖的分布，再只抽一个“最难拒绝”的答案进入 DPO/EXO/IPO/SPPO/NCA；它把 PL 的 168.4 GPU-hour 降到 64.4，同时把 HH-RLHF 上 DPO 的隐式 reward margin 从 0.349 拉到 2.723，却几乎没有改变外部 Reward（0.431→0.430）。

Motivation：真正的痛点不是“没有负例”，而是负例怎样进入损失

偏好训练常见两种压缩。BT 把一个 prompt 的候选压成二元胜负，只推开一个 rejected；PL 保留完整顺序，却递归要求第二名胜第三名、第三名胜第四名。HPS 指出后者在安全场景有语义冲突：当第二名和第三名都含有恶意内容时，训练“第二名优于第三名”等于暂时把有害回答放在正端；同时 PL 对 nn 个候选逐一前向并构造 nn 个子损失，成本随候选数线性上升（正文 4.1，HTML 行 144–153）。

量化证据有三层。第一，算力：PL、BT、HPS 的微调时间分别为 168.4±1.9、62.8±1.1、64.4±0.8 GPU-hour；HPS 相对 PL 少 104.0 GPU-hour / 61.76%，但比 BT 多 1.6 GPU-hour / 2.55%（正文 6，HTML 行 314–316）。第二，目标内 margin：HH-RLHF 的 DPO-BT 到 DPO-HPS，RM_DPO 从 0.349 到 2.723，绝对 +2.374、相对 +680.23%；RM_R-DPO 从 −0.455 到 2.040，跨过零点，百分比不具可解释性（表 2，HTML 行 240–242）。第三，外部质量几乎不变：同三行 Reward 为 0.431→0.430（−0.001，−0.23%），BLEU 为 0.230→0.232（+0.002，+0.87%）。所以论文最硬的结论是“更大的内部区分度与更低的 PL 成本”，而不是“外部评分大幅提高”。

更关键的是数据生成。每个原始 prompt 只有两个带人工偏好的回答，作者用 RLHFlow/Llama3-v2-DPO 扩充为 100 个，再由 Skywork-Reward-Llama3 排序（实验设置，HTML 行 305–313）。这让 HPS 获得丰富的候选集合，却也把“human preference”部分转化为“reward-model-labelled synthetic preference”。若外部排序器把某类安全拒答误判为低质，HPS 会比均匀/随机负例更集中地重复该偏差。

论文故事线、核心假设与权衡

故事线可以压成四步：

  1. 重定义信息价值。 不是所有 rejected 都同样有用；最接近 preferred、因而最难区分的 rejected 才提供高梯度信息。
  2. 把排序转成分布。 用固定的估计奖励 restr_{est} 经过温度 gammagamma 的 softmax 形成 qq；gammagamma 越大，越接近 hardest-negative。
  3. 只采一个负例。 不再把所有候选送入可训练模型反向传播；从 qq 抽一项，与首选构成常规成对优化。
  4. 给出极限解释。 当 gamma→∞gamma\to\infty，采样趋近最坏负例分布，极限目标等价于最大化 preferred 与最强 rejected 的最小间隔（定理 2–3，HTML 行 207–227）。

这条线依赖三组假设。统计理论假设隐式奖励有界、梯度有界、Hessian 有界且最优参数位于半径 BB 的球内（Assumption 1，HTML 行 187–192）；hardness 假设 restr_{est} 的排序与真正难度方向一致；安全语义假设所有 j≥2j\ge2 的候选都应该被整体压低。然而实际偏好往往有“两个都安全但风格不同”的弱序、不可传递偏好和多目标冲突，把所有 rejected 都当潜在有害会混淆“不同意”与“不安全”。

权衡也很清楚：HPS 用离线候选生成与外部标注成本换取训练期反向传播成本。论文确实只反传一个负例，但生成 100 个回答、用 8×L40S 做扩充与标注仍然昂贵；训练使用 4×L40S（附录 D.1，HTML 行 732–736）。因此 61.76% 是微调时长降幅，不是端到端数据生产+训练成本降幅。

方程级形式化与流程

给 prompt xx 和按偏好排列的候选 yτ(1)≻⋯≻yτ(n)y_{\tau(1)}\succ\cdots\succ y_{\tau(n)}，DPO 风格的隐式奖励是

rθ(x,y)=βlogπθ(y∣x)πref(y∣x).r_\theta(x,y)=\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}.

HPS 先在 rejected 集合上定义 hardness 分布（论文式 9，HTML 行 173–178）：

q(x,y)=exp(γrest(x,y))∑i=2nexp(γrest(x,yτ(i))),y∈{yτ(2),…,yτ(n)}.q(x,y)=\frac{\exp(\gamma r_{est}(x,y))}{\sum_{i=2}^{n}\exp(\gamma r_{est}(x,y_{\tau(i)}))},\qquad y\in\{y_{\tau(2)},\ldots,y_{\tau(n)}\}.

再把它代入“首选 vs 加权负例”目标（式 10）：

ℒHPS=𝔼d∼𝒟−logerθ(x,yτ(1))erθ(x,yτ(1))+N𝔼y∼p(y)[erθ(x,y)q(x,y)],N=n−1.\mathcal L_{HPS}=\mathbb E_{d\sim\mathcal D}-\log\frac{e^{r_\theta(x,y_{\tau(1)})}}{e^{r_\theta(x,y_{\tau(1)})}+N\,\mathbb E_{y\sim p(y)}[e^{r_\theta(x,y)}q(x,y)]},\quad N=n-1.

工程实现并不精确计算内层期望，而是 y−∼qy^-\sim q 单样本 Monte Carlo；于是一次更新仍像 DPO 的成对样本。极限上，定理 3 把目标写成

θ*=argmaxθ[rθ(x,yτ(1))−max1<j≤|τ|rθ(x,yτ(j))],\theta^*=\arg\max_\theta\left[r_\theta(x,y_{\tau(1)})-\max_{1<j\le|\tau|}r_\theta(x,y_{\tau(j)})\right],

即 maximin margin（式 14，HTML 行 224–227）。但“最大化内部 margin”并不自动推出“真实有害率下降”：两者之间还缺一个已校准、外部、与训练模型无共享偏差的安全度量。

for each prompt x:
    generate / retrieve n candidate responses
    keep y+ = rank-1 response
    score every rejected y_i with frozen r_est
    gamma <- linear schedule(-5, -3, -1, 1, 3, 5) at 20% intervals
    q_i <- softmax(gamma * r_est_i)
    sample one y- ~ q
    update chosen preference optimizer on (x, y+, y-)

注意论文方法段写“gamma>1gamma>1”，实验却从 −5 线性增至 5（正文 4.2 行 176 与实现行 315）。负 gammagamma 会优先抽低奖励、容易拒绝的样本，与“hard negative”方向相反；这可以解释成从 easy-to-hard curriculum，但论文没有把该相变写进定义或理论。

数据集、基准与指标

HH-RLHF 是多轮 helpful/harmless 对话；作者使用的公开扩充卡显示 train 161k rows，每条响应序列长度为 3（数据卡行 72–80）。PKU-SafeRLHF / PKU-Safety 是单轮安全偏好集合。本论文原始每 prompt 两回答，之后均扩成 100 个，所以“样本数”既包括 prompt 数也包括每 prompt 候选数，不能把 100 倍候选当作 100 倍独立人类标注。

四类指标：BLEU 衡量对参考答案的词面重叠，开放式对话中只是一项弱代理；Reward 来自外部 ArmoRM-Llama3；RM_DPO 是 preferred 与 rejected 的隐式 log-ratio 差；RM_R-DPO 再减去 0.01(|y+|−|y−|)0.01(|y^+|-|y^-|) 纠正长度（表 1，HTML 行 228–232）。人评是从两测试集各抽 15 个 prompt，共 30 题、4 个系统回答、20 名评分者，1–5 Likert，匿名并随机顺序（正文 6.1，行 321–323）。Qwen2.5-72B-Instruct 给 0–5 分和成对胜率。

逐层消融、超参敏感性与相变

候选数。 表 6 的 HH 消融中，DPO-HPS 的 RM_DPO 从 n=5n=5 的 0.600 增至 n=100n=100 的 2.723，+2.123、相对 +353.83%；DPO-BT 从 0.166 到 0.349，+0.183、+110.24%。BLEU 与 Reward 基本横盘。说明扩大支持集主要改变拒绝边界，不是首选答案的词面或外部 RM 质量。它也构成一个相变：候选池越大，遇到“高分但错误/有害”的 hard negative 越可能，HPS 的收益随极值统计增强。

迁移消融。 附录表 7 的 PKU HPS RM_DPO 为 1.191、1.620、2.164、5.725（n=5,20,50,100n=5,20,50,100）。但 n=50n=50 的 HPS 行把 BLEU/Reward 写成 0.230/0.307，与相邻行约 0.31/0.407 严重不一致（HTML 行 704–713），像排版或转录错误；在作者澄清前不据该两格作趋势判断。

beta 敏感性。 附录表 8 给 β=0.1,0.25,0.5,0.75,1\beta=0.1,0.25,0.5,0.75,1。HPS 的 RM_R-DPO 为 2.040, −0.828, −0.911, −0.925, −1.178；真正为正只发生在 0.1。HPS 相对 BT 在每个 beta 都较高，但“较高”不等于“绝对安全”：从 0.1 到 0.25，HPS RM_DPO 由 2.723 变 −0.146，出现明显符号翻转。KL 也从 11.767 降到 6.972，显示最大的 margin 伴随最大的策略漂移。论文把它总结为“所有 KL 值均优于 BT”（行 730–731），却没有讨论这个阈值。

gamma。 论文只给 −5→5 日程，未报告固定 γ\gamma、日程方向、更新频率的消融，也未测 gamma→∞gamma\to\infty 的数值稳定性。因此不能从实验推出“hardness 越尖越好”；理论极限与最优工程点之间仍为空白。

逐层归因缺口。 没有“100 候选+均匀单采样”“同一候选池 top-1 deterministic”“仅 easy-to-hard 日程”“oracle human hardness”等关键控制组。所以已观察到的收益无法完全拆成：多候选、外部 RM 排序、单样本、温度课程、HPS 损失五部分。

统计显著性

论文只为训练时间报告均值±波动：PL 168.4±1.9、BT 62.8±1.1、HPS 64.4±0.8 GPU-hour。主表 BLEU、Reward、margin、人评均是点估计；未报告随机种子数、标准差、置信区间、bootstrap、配对检验或多重比较校正。人评虽有 20 位评分者与 30 个 prompt，但也未给评分者一致性、题目级方差或效应区间。因此可以说 HPS 在这次运行里分数更高，不能严谨地说 +0.11 Likert 已统计显著。

Qwen 胜率的小数到三位并不等于高精度。若没有样本总数、配对重复结构和 judge 位置偏差估计，63.875% 与 58.712% 的差异不能按显示位数解释。最佳实践应对 prompt 做成对 bootstrap，并把 judge 随机种子、响应位置交换、单样本/Best-of-5 分开报告。

真正贡献、可复用设计与迁移潜力

真正贡献不是又造一个偏好损失，而是把“listwise 信息”拆成离线排序分布 + 在线单负例更新。这让任何只接受 (prompt, chosen, rejected) 的训练器都能利用 100 候选，却不付 PL 的全量反传成本。第二个贡献是把 hardest-negative 的 max-margin 直觉写进对齐理论；第三个是跨 DPO/EXO/IPO/SPPO/NCA 的正交插拔验证。

可复用设计包括：把 qq 替换成安全分类器、事实性 verifier、多目标 Pareto 分布；用小 RM 先缓存采样概率；按域或用户群设置 gammagamma；在在线场景把新失败回答加入候选池。迁移到代码生成时，restr_{est} 可用单元测试；数学推理可用过程 verifier；医疗问答可用指南一致性+拒答质量的多目标分数。但在任何高风险域，hard negative 的定义必须由外部实证校准，不能把“模型分高”直接当“最危险”。

论文自述限制

  1. 评测器预算（Section 7，HTML 行 337–340）。 作者明确说因预算使用开源 LLM 估胜率，更强的 GPT-4/Claude 可能更稳。这限制 judge 的外部有效性。
  2. 计算约束（Implementation，HTML 行 313–316）。 由于计算限制只做 LoRA rank 8；因此全参训练、更大模型与其他架构的结论未验证。
  3. 未在 Limitations 明说但由设置直接限定。 仅 HH-RLHF 与 PKU-SafeRLHF、一个 Llama3 参考家族、2048-token，不能覆盖长上下文、多语言或生产 red-team。论文限制段只写一项，以上两项按正文设置标注，避免冒充作者原话。

独立批判

  1. [构念效度] 因为 RM_DPO 正是由 logπθ/πreflog\pi_\theta/\pi_{ref} 导出，而 HPS 的定理 3 和训练目标直接最大化该间隔，所以 margin 的大幅上升部分是目标—指标同构；因此它证明“优化成功”，不能单独证明真实有害生成下降。
  2. [外部有效性] 因为每 prompt 的 100 候选由同一 DPO 模型扩充、再由 Skywork RM 排序，真正的人类信息仍主要来自原始二元对；所以“hard human preference”更准确地说是“hard reward-model preference”，迁移到不同生成器/文化群体可能失效。
  3. [评测偏差] 因为每方法采 5 个响应并对每项指标报最高分（HTML 行 313），而生产通常只返回一次采样，所以表 2 是 best-of-5 上界；因此不能直接当作单样本部署安全率。
  4. [超参稳健性] 因为 HPS 的 RM_R-DPO 在 β=0.1\beta=0.1 为 2.040、到 0.25 即变 −0.828，且最大 margin 对应 KL=11.767，所以主要结论依赖窄超参区；因此“稳健拒绝”需要在固定 KL 或固定外部质量下比较。
  5. [理论—实现一致性] 因为方法定义写 gamma>1gamma>1，实现却从 −5 开始；负温度反转排序，先采 easy negative，所以定理 2 的 hardest-distribution 极限没有覆盖完整训练路径；因此理论不能解释课程前半段收益。
  6. [归因] 因为缺少均匀单采样、deterministic top-1、固定 gamma 与 oracle ranking 控制组，所以单样本效率与 hard weighting 的贡献没有分离；因此 64.4 GPU-hour 与 margin 增益不能全部归功于“hard sampling”。
  7. [统计] 因为主表与人评没有方差/置信区间，且人评只含 30 prompt，DPO-HPS 对 BT 的 Likert 差仅 0.11；所以可以报告方向，不能断言效应稳定或显著。
  8. [数据一致性] 因为附录表 7 的 n=50n=50 HPS BLEU/Reward 0.230/0.307 与邻近值 0.31/0.407 不连贯，所以至少两格可能有转录问题；因此任何基于该点的“平滑 scaling law”都不可靠。

相关工作：问题来源与技术来源链

DPO：把 RLHF 化成二元分类

DPO 解决“先学 reward 再跑 PPO”的复杂性，通过闭式奖励参数化直接优化 chosen/rejected；arXiv 摘要明确称其稳定、轻量且无需训练时从 LM 采样（2305.18290v3，行 16–19）。遗留缺口是每次只见一个 rejected，且默认 BT 的标量、可传递偏好。HPS 沿用 DPO 的隐式奖励与训练器，却把多个 rejected 压成一个有信息的采样分布；DPO 的“成对接口”因此成为 HPS 的工程落点。

PRO：把二元偏好扩成完整排序

PRO 解决 pairwise 丢失宏观次序的问题，把任意长度排名递归对比，AAAI 2024 arXiv 摘要称其让概率排序对齐人类排序（2306.17492v2，行 16–19）。遗留缺口恰是 HPS 的出发点：PL/PRO 会要求次优有害回答胜过更差有害回答，并要对所有候选反传。HPS 保留“多候选带来信息”的来源，但拒绝递归排序，仅围绕首选构建 one-vs-hard-rest。

LiPO：用 learning-to-rank 重新加权列表

LiPO 把偏好优化系统化为 listwise learning-to-rank，并用 λ\lambda 权重区分不同偏好对；其摘要称在多项任务上胜过 DPO 变体（2402.01878v3，行 16–20）。遗留缺口是完整列表的成本与“哪类负例最值得更新”仍绑定在损失里。HPS 把权重前移到采样层，代价是每步只保留一个负例、可能增大梯度方差。

KTO：二元 desirable 标签也能对齐

KTO 用前景理论的损失厌恶解释偏好优化，只需 desirable/undesirable 标签；ICML 2024 arXiv 摘要强调 1B–30B 上可匹配成对方法，也明确“没有一种 HALO 普遍最好”（2402.01306v5，行 16–19）。遗留缺口是它不利用同 prompt 内 rejected 的相对难度。HPS 反向选择：不改变 optimizer 的行为经济学假设，只改变负例数据分布。两者可以组合成 HPS-KTO 的可检验方案。

开放挑战：可操作的 head-to-head 实验空白

理论

  1. 有噪 hardness 的一致性。 固定生成候选与 optimizer，对比 oracle human ranking、Skywork RM、加入 5/10/20% pair-flip 的 RM；主指标为真实人类 unsafe rate、margin calibration error 与定理界中的有效样本数。检验 HPS 是否在噪声超过阈值后比均匀采样更差。
  2. 有限 gamma 而非极限。 比较固定 gamma∈{−5,−1,0,1,3,5,10}gamma\in\{-5,-1,0,1,3,5,10\}、−5→5 日程、5→−5 反日程；在固定 KL 下画风险—质量 Pareto，验证 gamma→∞gamma\to\infty 是否真是最优，而非只会过拟合 RM。

工程与应用

  1. 端到端成本公平比较。 在同一 8×L40S 预算下比较 PL-20、HPS-100、均匀-100、online hard-negative mining；总成本必须包含生成、RM 标注、缓存、训练，并报 wall-clock、GPU-hour、能耗、显存峰值。
  2. 单样本部署安全。 对每 prompt 只采 1 个回答，与论文 best-of-5 并列；用独立安全分类器+人工红队，报告 jailbreak success、过度拒答、helpfulness 和 P95 延迟。这样才能判断 margin 是否转化为真实拒绝能力。
  3. 规模迁移。 在 7B/13B/70B、LoRA/全参、2048/32k 上做同一候选池 head-to-head；若 HPS 优势随模型规模消失，则它更像小模型数据效率技巧而非一般对齐原则。

新兴方向

  1. 多目标 hard negative。 用安全、事实、风格三个 RM 构造标量加权、Pareto-front 采样、随机目标采样三法；对比不同人群偏好下的最坏群体效用，检验单一 restr_{est} 是否压扁不可通约偏好。
  2. 循环/不可传递偏好。 在合成 rock-paper-scissors 偏好与真实多用户数据上比较 HPS、GPM/GPO 与 BT-DPO；指标为循环恢复率、群体 Condorcet regret 和个体胜率，直接测试 HPS 的标量排序假设。

近期工作速览

  1. Policy-labeled Preference Learning（ICML 2025）把行为策略标签纳入 regret-based likelihood，补的是离线偏好数据的行为策略错配；它提醒 HPS 的 100 候选来自特定生成策略，不应把生成器信息丢掉。
  2. AMPO（ICML 2025）用主动子集选择覆盖奖励极值与语义簇；它与 HPS 的直接对标应固定子集大小，区分“只采最难”与“兼顾多样性”。
  3. Energy-Based Preference Model / EPA（ICML 2025）指出 BT MLE 可能不唯一，并用强负例+大量免费弱负例逼近能量模型；它从偏好模型可识别性挑战 HPS 所依赖的标量排序。
  4. Beyond Bradley-Terry Models / GPM（ICML 2025）用向量嵌入表达循环偏好，查询复杂度仍为 O(K)；适合检验 HPS 在不可传递偏好下是否错误地强行线性排序。
  5. Right Now, Wrong Then（ICML 2025 PMLR 卷目录）研究偏好漂移下的非平稳 DPO；对 HPS 而言，缓存的 qq 会随人群/时间失效，应该增加时间戳与在线重估。
  6. PoisonBench（ICML 2025 PMLR 卷目录）评估偏好数据投毒；HPS 对高分 hard negative 的集中采样可能成为攻击放大器，需测少量 poisoned response 是否主导 qq。

结论

HPS 最值得带走的设计是：让多候选信息服务于采样，而不必全部进入反向传播。 它在同一 8B/LoRA 设定下把 PL 微调时间降 61.76%，并在多种 optimizer 上扩大隐式 margin；人评 3.93 也高于 BT 的 3.82，说明不仅是纯粹数值游戏。

但最关键的审慎结论同样明确：DPO-HPS 的 HH Reward 是 0.430，几乎等于 BT 的 0.431；最大的数字跃迁发生在被目标函数直接塑造的 margin。再加上 best-of-5、窄 beta 相变、gammagamma 定义—实现冲突与缺失显著性，HPS 应被定位为高效 hard-negative 对齐框架，而不是已完成真实安全闭环的方案。
