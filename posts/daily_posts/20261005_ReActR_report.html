ReActR

把错误轨迹变成可训练的反思能力

ACL 2026 Long · 43017–43028 2026-10-05 Error Taxonomy · SFT · GRPO

六类错误、困难度课程与分段反思奖励，使 Qwen3-4B 的五基准 Overall 从 LEMMA 的 52.4 提升到 57.3；但核心“反思”没有被直接测量，代码、数据、权重与统计区间也未公开。

一句话核心定位。 ReActR 不把数学推理中的错误样本当作应当过滤的噪声，而是把“错误类型—传播分析—局部修正—可迁移教训”组织成多轮监督，再用一个区分“发现错误”和“最终纠正”的分段奖励做 GRPO；它因此更像一套错误激活的后训练课程，而不是又一个单纯扩大正确答案数据量的方法。

2. Motivation：为什么“只学正确答案”不够

推理后训练的常见直觉是：高质量答案越多越好，错误轨迹应被过滤掉。ReActR 反过来追问：如果模型永远只看到完成良好的证明，它究竟在哪里学会“何时怀疑自己”“错误从哪一步开始传播”“修正后应抽象出什么教训”？论文认为，正确轨迹主要传递如何做对，错误—修正对才显式传递如何从失败返回正确轨道。

这个痛点不是纯概念性的。以 Qwen3-4B 为例，论文的普通 SFT 基线在 GSM8K 为 79.8、MATH 为 48.6，而 ReActR 为 91.1 和 65.7，分别高 11.3 和 17.1 pp；五个测试集合并后的 Overall 从 42.4 到 57.3，绝对增加 14.9 pp、相对增加 35.14%（Table 2，PDF p.7 / 会议页 43023）。更重要的是，收益没有停留在训练域：DeepMind Mathematics 从 47.9 到 68.9、College Math 从 22.5 到 35.2、OlympiadBench-Math 从 13.2 到 25.6，绝对提升分别为 21.0、12.7、12.4 pp。这里能推出的是：这套数据与奖励组合在作者的数学设置中显著强于其普通 SFT 实现；不能直接推出收益完全来自“反思机制”，因为训练数据规模、教师模型、数据难度与 GRPO 同时变化。

论文先对错误做六类划分（Table 1，PDF p.3 / 会议页 43019）：Calculation Error（CA，计算错误）、Formula Confusion（FC，公式混淆）、Question Misinterpretation（QM，题意误解）、Missing Step（MS，缺失步骤）、Confusing Concept（CC，概念混淆）、Nonsensical Output（NO，无意义输出）。这一步把“答案错了”拆成可操作的诊断标签。标签本身不是最终贡献；真正关键是标签如何控制后续的数据生成、错误覆盖与奖励设计。

3. 论文故事线、假设与权衡

论文的故事线可概括为四步。

  1. 先让学生暴露真实失败模式。 作者用 Qwen3-4B 在 MATH 与 GSM8K 上以 temperature 0.6 自生成推理，筛出错误答案，得到学生自然发生的失误分布。
  2. 再用强教师补齐“难而有用”的错误。 Gemini 2.5 Pro 面向 MATH level 3–5 题目定向生成错误，重点覆盖高频的 QM、CC、CA，避免数据只被容易产生的表面计算错误主导。
  3. 把错误变成结构化反思监督。 教师不仅给正确答案，还指出错误类型、定位错误步骤、解释传播影响、给出修正版推理，并总结可迁移教训。最终数据由 25K 错误—修正轨迹与 25K 正确轨迹组成，共 50K 多轮样本（方法部分与 Appendix A.2，PDF pp.3–5、11）。
  4. 用分段奖励强化“发现 + 修正”。 GRPO 不只看最后答案：初始答案错误时，正确识别错误得 0.3，最终纠正再得 0.7；初始答案正确且反思确认正确得 1.0。模型既要避免盲目翻案，也要在真正错误时完成修复（Figure 6，PDF p.5 / 会议页 43021）。

核心假设有三个。第一，错误轨迹含有正确轨迹没有的局部决策边界信息；第二，显式错误分类能让有限预算覆盖更有教学价值的失败；第三，验证器可检查的数学答案足以为反思建立稳定的强化信号。相应权衡也很清楚：教师生成可快速规模化，但会继承教师偏差；分段奖励可归因“发现”与“修正”，却把反思压缩成少数离散状态；多轮反思提高纠错机会，但训练和推理 token 成本上升。

4. 方程级形式化与流程

4.1 数据单元

令题目为 xx，学生初始轨迹为 y(0)y^{(0)}，答案判定器为 V(x,y)∈{0,1}V(x,y)\in\{0,1\}。对错误轨迹，教师生成结构化反思：

z=(c,ℓ,e,y(1),g), z=(c,\ell,e,y^{(1)},g),

其中 cc 是六类错误标签，ℓ\ell 是错误发生位置，ee 是错误如何传播的解释，y(1)y^{(1)} 是修正轨迹，gg 是可迁移的 lesson。训练样本可写为 (x,y(0),z)(x,y^{(0)},z)。对正确轨迹，数据仍保留“确认正确”的反思回合，防止模型形成“一反思就推翻”的偏差。

监督阶段优化标准自回归负对数似然：

ℒSFT(θ)=−∑(x,s)∈𝒟∑tlogπθ(st∣x,s<t), \mathcal L_{\text{SFT}}(\theta)=-\sum_{(x,s)\in\mathcal D}\sum_t \log \pi_\theta(s_t\mid x,s_{<t}),

其中 ss 串接初始推理、反思、修正与总结。论文没有给出新的 SFT 方程；上式只是对其已描述训练过程的标准形式化。

4.2 五种奖励状态

记 a0=V(x,y(0))a_0=V(x,y^{(0)})，反思判断 d∈{correct,wrong}d\in\{\text{correct},\text{wrong}\}，修正后答案为 a1=V(x,y(1))a_1=V(x,y^{(1)})。Figure 6 给出五种情形：

初始答案 反思判断 修正结果 奖励 含义
正确 确认正确 不需要修正 1.0 正确校准，不制造错误
正确 错判为错误 修成错误 0.0 惩罚盲目自我怀疑
错误 识别错误 修正正确 0.3 + 0.7 = 1.0 发现与纠正都成功
错误 识别错误 仍修错 0.3 诊断有价值，但修复失败
错误 错判为正确 未修正 0.0 未激活反思

可把它写成：

r=𝟙[a0=1,d=correct]+0.3𝟙[a0=0,d=wrong]+0.7𝟙[a0=0,d=wrong,a1=1]. r=\mathbb 1[a_0=1,d=\text{correct}] +0.3\,\mathbb 1[a_0=0,d=\text{wrong}] +0.7\,\mathbb 1[a_0=0,d=\text{wrong},a_1=1].

这一定义揭示了一个容易忽略的性质：正确答案被正确确认与错误答案被完整修复同为 1.0，所以奖励鼓励的是任务成功状态，不是“越多反思越好”。但它也没有区分高置信正确与侥幸正确，没有对反思文本的因果忠实度打分。

4.3 GRPO 的组内比较

论文说明每题采样 5 个响应、训练 3 epochs、固定学习率 10−610^{-6}，使用 verl 运行 GRPO（Appendix A.2，PDF p.11）。论文未写出完整目标；可依据 GRPO 的标准做法把作者描述形式化为：对同一题的 G=5G=5 个响应，先做组内标准化优势

Âi=ri−μrσr+ϵ, \widehat{A}_i=\frac{r_i-\mu_r}{\sigma_r+\epsilon},

再用裁剪比率 ρi=πθ(yi∣x)/πθold(yi∣x)\rho_i=\pi_\theta(y_i\mid x)/\pi_{\theta_{old}}(y_i\mid x) 优化

J(θ)=1G∑imin(ρiÂi,clip(ρi,1−ε,1+ε)Âi)−βKL(πθ,πref). J(\theta)=\frac{1}{G}\sum_i \min\left( \rho_i\widehat{A}_i, \mathrm{clip}(\rho_i,1-\varepsilon,1+\varepsilon)\widehat{A}_i\right) -\beta\,\mathrm{KL}(\pi_\theta,\pi_{ref}).

这段是对流程的标准化重述，不是 ReActR 论文逐字给出的方程。论文没有报告 ε\varepsilon、β\beta、KL 实现细节或它们的敏感性，因此不能据此复现完整 GRPO 配置。

4.4 伪代码

输入：MATH、GSM8K 题目；学生 Qwen3-4B；教师 Gemini 2.5 Pro
1  学生以 temperature=0.6 采样初始推理，保留真实错误
2  教师在 MATH level 3–5 定向合成 QM/CC/CA 等困难错误
3  对每个错误：标类型 → 定位首个关键错误 → 分析传播
                  → 生成修正轨迹 → 总结 lesson
4  混合 25K 错误—修正样本与 25K 正确轨迹
5  用 LoRA 做 4 epochs SFT
6  每题采样 5 个响应，按五状态奖励计算组内优势
7  用 GRPO 训练 3 epochs
输出：能确认正确、发现错误并修正的推理模型

6. 数据集、基准与指标

训练域包括 GSM8K 与 MATH。GSM8K 以小学到初中风格的多步文字题为主；MATH 难度更高、覆盖代数、几何、数论等。论文还把 MATH level 3–5 用作教师定向错误合成的主要来源，因此 MATH 不只是测试集名称，也是困难课程的核心来源。

评测分成两组：in-domain 为 GSM8K、MATH；out-of-domain 为 DeepMind Mathematics、College Math、OlympiadBench-Math。主指标是 Pass@1，即每题一个输出是否得到正确最终答案。表中的 In AVG 是前两个基准均值，Overall 是五个基准的平均。该设计能观察是否从训练域迁移到不同数学分布，但不能验证代码、开放式科学推理或无法自动判定答案的任务。

评价协议还有三个边界。第一，Pass@1 只看最终答案，不能测反思定位是否正确；第二，论文没有报告每个基准的样本裁剪、提示模板全文和解码长度上限；第三，Figure 5 的 MATH 难度分层结果注明是 10 次 inference runs 的平均，但 Table 2 / 3 没有标准差或置信区间。因此本文把主表差异视为观察到的点估计，不称为“统计显著”。

7.4 跨骨干结论

ReActR 在三种骨干、15 个“模型 × 单项基准”格子全部高于 LEMMA，这是比单一平均值更扎实的稳定性证据。但这种一致性仍不是统计显著性：同一训练数据和教师信号可能给三种骨干带来同方向偏差，论文又没有多随机种子。定量上，ReActR 对 LEMMA 的 Overall 优势在 3.5–4.9 pp；这比它对普通 SFT 的 13.5–14.9 pp 小很多，说明相当一部分收益来自“更好的数学训练数据”这一大类因素，而非只有 ReActR 特有的分段奖励。

最有信息量的不是“每个模块都有效”这句常规结论，而是三个非线性现象。第一，Out-Both 在 MATH 上比完整模型低 19.4 pp，损失大于单独移除错误类型（9.5）或难度（5.4）之和 14.9 pp，说明两种课程信号可能互相放大；但没有多种子，不能断言这 4.5 pp 差额是稳定交互效应。第二，All-Error 直接失败，说明“错误有价值”不等于“错误越多越好”；25K 正确轨迹承担锚定正确策略的作用。第三，去掉 GRPO 仍达 88.4 / 62.1，说明大部分提升在 SFT 阶段已经建立；GRPO 提供额外 2.7 / 3.6 pp，而不是全部收益来源。

8.2 数据规模曲线

Figure 7a（PDF p.7）展示 augmented data 从 10K 增至 50K 时 GSM8K 与 MATH 总体上升，MATH 的上升更明显。图中没有逐点数字标签，因此本文不伪造精确矩阵；只能可靠推出在作者测试范围内尚未明显饱和。Figure 7c 还显示混入更多 MetaMath 数据后平均性能上升，但同样只给图形、无精确表格。这支持“高质量正确轨迹仍能补充错误课程”，却无法计算每 1K 样本的边际收益。

8.3 错误分布变化

Figure 7b 显示增强前后 QM 与 CA 的占比下降，而 CC 与 Others 上升。作者解释为定向合成补充了更复杂概念错误。由于柱状图没有精确数值标签，本文仅保留方向性结论。它提示数据策展不是简单复制自然错误频率，而是主动改变错误分布；相应风险是该分布可能更接近 Gemini 2.5 Pro 的“教学想象”，不一定等于真实用户失误。

8.4 超参数敏感性

论文未报告。 奖励拆分固定为 0.3（识别）+0.7（纠正），但没有比较 0.1/0.9、0.5/0.5 或连续评分；GRPO 的组大小固定为 5，没有组大小曲线；SFT 学习率 10−510^{-5}、GRPO 学习率 10−610^{-6}、4 / 3 epochs、temperature 0.6 都未做敏感性分析。故不能判断方法是否对奖励比例、采样温度或训练长度脆弱，也不能确认 0.3/0.7 是机制上合理还是单点调参结果。

8.5 相变判断

有两个“相变候选”，但证据强度不同。All-Error 失败显示数据混合从“有正确锚点”跨到“全错误”时出现训练崩溃，这是定性相变；但作者没有扫描 10%、25%、50%、75%、100% 错误比例，因此阈值未知。数据规模 10K→50K 的曲线没有显示突变，只显示持续增益，故不能宣称存在规模相变。

9. 统计显著性与可重复性

论文没有为 Table 2 / 3 报告随机种子数、标准差、置信区间或显著性检验。Figure 5 明确说 MATH 难度分层结果是 10 次 inference runs 的平均，但仍没有误差条。Pass@1 评测本身可按题目级 bootstrap 构造区间，作者未提供。因此：

  • 能说三种骨干的点估计方向一致，且部分差距较大；
  • 不能说 0.3 pp 的 Mistral Olympiad 优势稳定，也不能比较 3.5 与 3.6 pp 哪个“更强”；
  • 不能把 Table 3 中 2.7–3.6 pp 的 GRPO增益直接视为跨 seed 因果效应；
  • 没有代码、数据和权重链接，使独立复现无法从报告时点开始。

更合适的最小统计方案是：三个训练 seed；题目级 paired bootstrap；报告均值、标准差与 95% CI；对五基准多重比较做 Holm 修正；对反思识别本身报告 precision、recall、ECE 与错误类型混淆矩阵。

10. 真正贡献、可复用设计与迁移潜力

10.1 真正贡献

第一，错误被提升为课程单元。 以前很多方法要么在推理时反复自评，要么在训练时用错误答案当负例。ReActR 把错误类型、难度和传播分析串成数据策展回路，使错误不只是“负标签”，而是决定训练覆盖的控制变量。

第二，奖励把诊断与修复拆开。 错误识别成功但修正失败仍得 0.3，这让部分正确的内部决策获得学习信号。虽然奖励仍粗糙，但它比“最终答案全有或全无”更接近反思的分阶段结构。

第三，正负轨迹混合成为必要条件。 All-Error 失败而 All-Correct 明显落后，说明可复用的设计不是“喂错误”，而是让正确轨迹稳定基本策略、错误轨迹塑造恢复策略。这个结论比某个特定错误标签更值得迁移。

10.2 可复用模块

  1. 错误本体 + 配额采样。 对代码可对应到语法、类型、边界、算法、复杂度、工具调用错误；对 Agent 可对应到观察遗漏、计划冲突、工具选择、状态更新与停止错误。
  2. 首错定位。 与其整段重写，先找到最早导致后续偏离的决策点；这可减少信用分配跨度。
  3. 反思 lesson。 让修正后输出一条未来可检索的规则，便于构建 episodic memory 或错误簿。
  4. 分段可验证奖励。 当任务有单元测试、定理检查器、模拟器状态或数据库约束时，可分别奖励识别、修复和最终完成。
  5. 正误混合课程。 保持正确策略的锚点，再逐步提高困难错误比例，避免只学会怀疑。

10.3 迁移潜力

迁移到代码最直接，因为单元测试可同时验证初始与修正版本；但需避免模型通过删测试或硬编码投机。迁移到工具 Agent 时，可把“错误传播”定义成错误工具调用如何污染后续状态，并用环境回滚验证修复。迁移到科学问答较难，因为最终答案可能不可自动判定；需要引文一致性、单位检查、符号约束或外部模拟器，不能照搬数学答案匹配。迁移到开放式写作最弱，因为“纠正”缺少客观验证器，教师偏好会主导奖励。

11. 问题来源 / 技术来源链

11.1 Self-Refine：从推理时自反馈到可训练反思

解决什么。 Self-Refine 让同一模型生成、反馈并迭代改写，无需额外训练；论文报告在 7 类任务上平均约 20% 绝对提升（NeurIPS 2023 正式工作）。
遗留缺口。 它主要发生在推理时：模型是否能可靠识别错误、何时停止，以及反馈是否真的对应首个关键错误，没有训练级保证。
ReActR 如何回应。 ReActR 把“生成—反馈—修正”下沉到后训练数据，并用答案验证器奖励错误发现与最终修正。
设计如何传递。 Self-Refine 的迭代回路传递为 ReActR 的多轮样本结构，但 ReActR 增加错误本体、混合课程与 RL 信号。

11.2 RefAug：从“答案之外”学习反思说明

解决什么。 RefAug 为指令数据附加反思与扩展信息，使模型不只模仿答案，还学习解题后的解释与替代思路。
遗留缺口。 通用反思增强未明确控制错误类型和难度，也没有把“识别错误”和“修正错误”拆成奖励。
ReActR 如何回应。 它用六类错误和 MATH level 3–5 定向采样，明确覆盖难错，并把 RefAug 作为 30K 基线；Qwen Overall 47.6 对 57.3，差 9.7 pp（Table 2）。
设计如何传递。 “答案后再学习一层元信息”被保留，但元信息从泛化反思改为首错定位、传播与 lesson。

11.3 LEMMA：从错误修正数据到类型—难度课程

解决什么。 LEMMA 系统利用错误解答及纠正进行数学推理训练，是与 ReActR 最直接的技术前身。
遗留缺口。 错误样本如果不按类型和难度策展，容易被频繁、浅层错误主导；仅监督纠正也无法单独奖励“发现错误”。
ReActR 如何回应。 它增加错误分类与困难度导向，再叠加 GRPO。三种骨干 Overall 均高于 LEMMA：Qwen +4.9、Mistral +3.6、Llama +3.5 pp（Table 2）。
设计如何传递。 LEMMA 的错误—纠正轨迹成为数据骨架；ReActR 加入课程控制与分段奖励。与此同时，LEMMA 用 60K、ReActR 用 50K，使结果兼具一定样本效率信号，但不是严格算力匹配实验。

11.4 DeepSeek-R1：从可验证结果奖励到反思专用奖励

解决什么。 DeepSeek-R1 表明大规模 RL 可从可验证数学与代码奖励中涌现长链推理与自检行为。
遗留缺口。 只看最终正确与否的稀疏奖励难以区分“发现错误但没修好”与“根本没发现”，信用分配跨度长。
ReActR 如何回应。 它显式给错误识别 0.3、最终修正 0.7，并对正确答案的正确确认给 1.0。
设计如何传递。 可验证结果 RL 的框架被保留，但奖励结构围绕反思状态机重新设计；代价是依赖 gold answer，开放域迁移受限。

11.5 非线性技术演进树

12. 论文自述限制

  1. 教师质量上限。 作者指出 Gemini 2.5 Pro 生成的数据仍可能含细微不准确或歧义，模型质量受教师能力限制（Limitations，PDF p.8 / 会议页 43024）。这意味着“错误课程”本身也可能教错。
  2. 复合错误难以一次修完。 当前流程聚焦 dominant error；修复一个错误后可能暴露另一个，未来需要迭代多轮纠正（Limitations，PDF p.8）。因此现有 reward 状态机更适合单个主要错误。
  3. 规模与任务域有限。 数据规模仍有限，作者明确提出扩展数据，并迁移到代码等其他可验证域（Limitations，PDF p.8）。因此论文证据不支持开放域通用反思。

13. 独立批判

  1. [测量效度] 因为论文的核心主张是学会“反思”，但主表只报告最终答案 Pass@1，没有错误检测 precision / recall、首错定位准确率、修正成功条件概率或 lesson 质量，所以性能提升不能区分“真正更会反思”和“吸收了更多数学知识”。
  2. [归因] 因为 ReActR 同时改变数据量、错误类型分布、难度分布、教师质量与 GRPO，而基线样本量从 SFT 15K、RefAug 30K 到 MetaMath/LEMMA 60K 不等，所以 Table 2 证明系统整体有效，却不能把 3.5–4.9 pp 的 LEMMA 优势唯一归因于错误激活奖励。
  3. [教师偏差] 因为 Gemini 2.5 Pro 同时参与合成困难错误、诊断错误、生成修正与 lesson，所以训练信号高度相关，模型可能学习教师特有措辞与错误观，而不是对自然用户错误分布稳健的反思策略。
  4. [奖励设计] 因为“正确→确认正确”和“错误→发现并修正”都得 1.0，且只按最终答案判定，所以奖励无法区分高质量因果解释与偶然猜中；模型可能通过简短重算获得相同回报，而不真正定位传播链。
  5. [统计] 因为 Table 2 / 3 没有 seed、标准差、区间或检验，所以 Mistral Olympiad 上仅 0.3 pp 的优势可能小于训练与解码噪声；即便三个骨干方向一致，也不能替代配对统计。
  6. [可重复性] 因为 ACL 页面未给代码、数据、权重或 arXiv，Appendix 也未报告 LoRA rank、GRPO clip / KL 等关键配置，所以独立团队无法完整复现 50K 数据构造和 RL 阶段。
  7. [成本] 因为论文只报告数据合成超过 100M tokens、API 略高于 700 美元，没有 GPU 时数、峰值显存、训练吞吐、推理 token 与延迟，所以无法判断 2.7–3.6 pp 的 GRPO 增益是否值得生产部署。
  8. [外推] 因为奖励依赖 gold answer，五个评测也全是数学，所以能推出的是“可验证数学反思有效”，不能推出对开放式事实核查、长程 Agent 或科学解释同样有效。

14. 开放挑战：可执行的 head-to-head 实验空白

14.1 理论

错误轨迹为何有额外信息？ 做严格 head-to-head：固定题目、token 数、教师和最终正确解，把 50K 数据分为（A）正确解重复、（B）随机错误+正确解、（C）真实错误+正确解、（D）类型配额错误+正确解。比较样本复杂度与错误检测互信息，验证收益来自“决策边界信息”还是单纯更长文本。

奖励分解是否可识别？ 固定 SFT checkpoint，比较 final-only、0.1/0.9、0.3/0.7、0.5/0.5、learned critic 五种奖励。除最终正确率外，测错误检测 AUPRC、条件修正率 P(a1=1∣a0=0,d=wrong)P(a_1=1\mid a_0=0,d=wrong) 与过度翻案率。只有这样才能判断 0.3 是否有机制意义。

正误混合的崩溃阈值。 将错误比例从 0% 扫到 100%，每 10% 一档、每档 3 seeds；画能力、校准和训练稳定性曲线，直接定位 All-Error 失败前的临界区，而不是只比较两个端点。

14.2 工程与应用

等算力对照。 让 ReActR、LEMMA、RefAug 和正确轨迹 SFT 使用相同 50K 样本、相同总 token、相同 LoRA rank、相同 GPU 时数；同时报告训练成本与 Pass@1。当前不同样本量使样本效率和方法增益混在一起。

服务级价值。 在相同准确率目标下，比较无反思、固定一次反思、置信触发反思、ReActR 四种策略的平均输出 token、P50/P95 延迟、能耗与成本；重点测试“只在可能错误时激活”能否抵消多轮开销。

代码迁移。 在 HumanEval+、MBPP+、SWE-bench Verified 的可复现子集上，对比 final-only RL、unit-test error taxonomy 和 ReActR 风格首错定位；奖励必须防止篡改测试。看收益是否落在 compile error、logic error 或 repository navigation 的不同层级。

14.3 新兴方向

工具 Agent 的可回滚反思。 在 WebArena 或 τ-bench 中记录首个错误工具调用，比较“完整重启”“状态回滚到首错”“文本反思但不回滚”。以任务成功、额外调用数和状态污染深度为指标，检验错误传播分析是否真能缩短恢复路径。

过程验证器联合训练。 将 ReActR 与独立 process reward model 做 head-to-head：相同 rollout 数下，比较最终答案奖励、步骤奖励、两者组合；用人工标注子集评估 verifier 是否只是复制教师偏差。

复合错误的迭代纠正。 构造每题含两个已知错误的诊断集，比较单轮 dominant-error 修正与最多三轮的逐错修正。指标应包含首错定位、第二错暴露率、累积成功率与 token 开销，直接回应作者自述限制。

15. 近期值得跟踪的工作

  1. LLMThinkBench: Do LLMs Overthink Basic Math Reasoning?（ACL 2026 Findings）——把“推理越长越好”拆成过度思考和正确性问题，适合作为 ReActR 是否制造冗余反思的外部评测。
  2. SATQuest（ACL 2026）——把评测扩展到标准化考试式的多领域推理，可检验数学错误本体是否能迁移。
  3. ReEfBench（ACL 2026）——直接关注反思是否有效，为 ReActR 缺失的“反思本身”测量提供更合适的框架。
  4. Scaling Behaviors of LLM Reinforcement Learning Post-Training（ACL 2026）——从规模维度审视 RL 后训练，能帮助判断 ReActR 的 5-rollout GRPO 是否处于收益递减区。
  5. Why Does Reinforcement Learning Generalize?（ACL 2026）——关注 RL 泛化来源；与 ReActR 结合可区分“错误课程覆盖”与“策略优化”各自的 OOD 贡献。
  6. LRBench and Judge-R1（ACL 2026 Findings）——面向长推理与 judge 训练，适合测试反思奖励是否在长轨迹中仍能正确分配信用。
  7. How Instruction and Reasoning Data Shape Post-Training（ACL 2026）——系统讨论后训练数据构成，可为 ReActR 50:50 正误比例提供更强的配比基线。

16. 结论

ReActR 最值得看的地方，不是它把“反思”写进提示，而是把错误从被丢弃的副产物变成可控课程：真实错误提供分布，教师补齐困难类型，结构化纠错提供监督，分段奖励再区分发现与修复。三种骨干上相对 LEMMA 的 Overall 提升稳定在 3.5–4.9 pp；Qwen3-4B 的 Overall 为 57.3，对 LEMMA 52.4 提升 4.9 pp / 9.35%。消融更尖锐：去掉错误类型导向，MATH 从 65.7 降到 56.2；类型和难度都去掉则降到 46.3，损失 19.4 pp。

但最关键的未闭环点也正是“反思”：论文没有直接测错误检测、首错定位或 lesson 质量，没有多 seed 显著性，没有完整等算力对照，也没有公开代码、数据或权重。因而最稳妥的结论是：错误类型 × 难度课程 × 正误混合 × 分段 GRPO 是一套强而可迁移的数学后训练配方；它是否真的产生了可靠、可校准、跨域的自我反思能力，仍需专门评测。
