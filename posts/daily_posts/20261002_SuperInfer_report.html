SuperInfer

把“换出 KV”从内存补丁变成 SLO 调度原语

arXiv:2601.20309v2 2026-10-02 RotaSched · VLT/LVF · DuplexKV

DuplexKV 将 16 GB 双向 KV 迁移从 1556.15 ms 压至 46.80 ms；在 GH200 高负载下，SuperInfer 的 TTFT SLO 达标率最高提高 74.7 个百分点，但硬件外推、Pie 对比与统计区间仍缺失。

一句话核心定位：SuperInfer 面向 NVIDIA GH200 这类 CPU–GPU 紧耦合 Superchip，把请求在 HBM 与 DRAM 间的 KV 迁移改写为由延迟欠账驱动的主动轮转；其真正贡献不是“更多主存”，而是让调度目标、数据布局和全双工传输在同一条服务关键路径上闭环。

报告日期： 2026-10-02　领域： 效率与系统（LLM serving、KV cache、SLO、Superchip）　核心论文： Jiahuan Yu、Mingtao Hu、Zichao Lin、Minjia Zhang，MLSys 2026。

2. Motivation：为什么“有 900 GB/s”仍然服务不快

LLM 在线推理的瓶颈不是单一算子，而是一个随请求生命期变化的资源耦合：每个请求的 KV cache 随生成长度线性增长，HBM 容量固定；高到达率下，新请求卡在 waiting queue，旧请求占着 HBM，又不能无限扩大 batch。TTFT 关心“何时开始出第一个 token”，TBT 关心“相邻 token 是否持续可见”，两者对暂停的敏感度并不对称。

论文先用静态策略暴露矛盾（§3.1，Figure 1，正式 PDF pp.3–4）：Waiting-First 优先新请求，TTFT 变好但生成中的请求长时间暂停，TBT 恶化；Swapped-First 优先恢复已换出请求，TBT 得到保护，却退化为接近 FCFS，swap space 也未被充分利用。也就是说，“换谁”本身就是 SLO 决策，而不是 OOM 后的被动清理。

第二个痛点是带宽。传统 PCIe Gen5 x16 单向带宽约 32–64 GB/s；论文 Figure 2 显示，只有把模拟 swap bandwidth 推到 PCIe 上限以上，P99 TTFT 与 P99 TBT 才继续明显下降（§3.2，PDF p.4）。低带宽造成两层 HOL blocking：D2H 太慢，waiting backlog 清不掉；H2D 太慢，rotary/swapped 请求又在恢复队列排队。

第三个痛点最反直觉：GH200 的 NVLink-C2C 理论双向总带宽达 900 GB/s，但直接移植 vLLM 的小块拷贝只测到约 10 GB/s，低于可实现带宽的 5%（Figure 4–5，PDF p.4）。论文进一步测得 Grace DRAM 是现实上限：并发 D2H/H2D 约 200+200 GB/s，而非链接标称的 450+450 GB/s，因为单 NUMA 节点 DRAM 带宽为 384 GB/s 且总体呈半双工约束。因而问题不是“买了快链路就完成”，而是 PagedAttention 的碎片化布局、过小 copy、串行方向和数据竞争共同把硬件能力锁住。

量化证据由三条链闭合：硬件标称 900 GB/s → DRAM 实测约 384 GB/s 总预算 → 现有栈约 10 GB/s。SuperInfer 的目标不是宣称越过物理极限，而是把软件从 10 GB/s 拉近 192+192 GB/s 的并发可实现上界，同时把这项吞吐能力交给 SLO 调度器使用。

3. 论文故事线、假设与权衡

故事线分两半。RotaSched 解决“谁应该运行”，把请求状态从 waiting / running 扩展为 waiting / running / rotary；rotary 表示请求暂时停止、KV 已在 CPU DRAM、等待下一次轮转。DuplexKV 解决“轮转能否足够快”，通过 eager block rotation、block-first layout、批量传输 kernel 和跨迭代流水线把换入换出藏在模型执行后面（Figure 6、15，PDF pp.5、9）。

这套设计建立在四个假设上：

  1. GH200/同类 Superchip 具有远高于 PCIe 的 CPU–GPU 互连和足够大的主存；论文在单个 GH200 上分配 400 GB Grace DRAM 给 KV，保留 80 GB 给 OS/runtime（§5.2，PDF p.9）。
  2. 调度 + 传输能被模型执行覆盖。论文汇总主实验的平均时延为调度 7.63 ms、KV 传输 15.8 ms、模型执行 69.82 ms；仅 0.021% engine iteration 出现未完全覆盖导致的 stall（§5.3.4，PDF pp.11–12）。
  3. 服务目标可用固定 TTFT/TBT SLO 表达。主实验设 TTFT 5 s、TBT 100 ms，而不是按用户、请求类型或价格等级动态变化（§5.2，PDF p.9）。
  4. KV 迁移是无损的：不裁剪 token、不压缩精度，因此模型输出质量保持不变；代价是仍要支付全量字节移动和 GH200 特定工程复杂度。

核心权衡很清楚：主动抢占可清 waiting backlog，却可能伤害正在生成请求的 TBT；更大的 transfer budget 能压低两类尾延迟，却要求更强传输引擎；更积极保护 rotary 请求会牺牲新请求。论文没有消除 Pareto 前沿，而是用可解释参数把位置暴露出来。

4. 方程级形式化与伪代码

4.1 Virtual Lag Time

RotaSched 用 Virtual Lag Time（VLT）把三种状态放到同一优先级轴上。根据 §4.2.2、Equation（PDF p.6）：

[ _i = {αReLU(tnow−tlast−βBSB),i∈rotaryReLU(tnow−tarr−βFSF),i∈waiting−(tnow−trun),i∈running\begin{cases} \alpha\,\mathrm{ReLU}(t_{now}-t_{last}-\beta_B S_B), & i\in rotary\\ \mathrm{ReLU}(t_{now}-t_{arr}-\beta_F S_F), & i\in waiting\\ -(t_{now}-t_{run}), & i\in running \end{cases}

]

论文把 (S_B) 定义为 TBT SLO、(S_F) 定义为 TTFT SLO；(t_{last}) 是最近 token 时间，(t_{arr}) 是到达时间，(t_{run}) 是本次进入 running 的时间。正 VLT 表示“已经落后”，负 VLT 表示“已得到较多执行”；() 控制 TBT 相对 TTFT 的敏感度，(_B,_F) 是容忍区间。

4.2 Largest-VLT-First

每个 engine iteration：
  若 HBM 足以容纳所有请求：回退 FCFS
  否则：
    1. 为 waiting / rotary / running 请求计算 VLT
    2. 按 VLT 降序排序为 L
    3. 从 L 头部选择 waiting/rotary，请求块数不超过 B_HBM + B_xfer
    4. 若空间不足，从 L 尾部抢占 VLT 最小的 running 请求
    5. DuplexKV 并发执行换入与 eager 换出；下一迭代使用准备好的 batch

该流程来自 §4.2.3 与 Figure 10（PDF p.6）。(B_{xfer}) 不是抽象超参：它是每轮允许轮转的 KV block 数，直接把可用带宽转换为“每轮可偿还多少 SLO 欠账”。这也是论文最可迁移的设计观：系统容量应进入调度约束，而不是藏在事后 backpressure 中。

4.3 DuplexKV 的数据竞争规避

如果同一请求正在 H2D 恢复，同时 D2H 又写回更新过的 KV，朴素全双工会发生覆盖竞态。DuplexKV 不等到抢占才整体换出，而是在 block 写满后立即把 immutable block eager-copy 到 DRAM 并标为 synced；抢占时 synced HBM block 可直接丢弃，只有未同步尾块需要处理。配合 block-first layout，把跨层、跨头散落的小 segment 合并为约 4 MB 传输单元，再把同方向 copy 合并进大 kernel（§4.3、Figure 11–14，PDF pp.7–8）。

6. 数据集、模型、指标与实验设计

实验在 NVIDIA GH200 NVL2 上完成；每个 Superchip 有 144 GB HBM + 480 GB DRAM，用 numactl 固定同 NUMA 内存（§5.1，PDF p.8）。模型覆盖 Dense 与 MoE：LLaMA-3-8B、Qwen2.5-32B、Mixtral-8x7B。请求来自 ShareGPT 与 LMSYS-Chat-1M，到达间隔按 Poisson 分布采样；这能模拟随机到达，但不等于真实生产的 burst、时段相关性或多租户优先级。

主要指标为 SLO attainment rate：满足 TTFT 或 TBT 阈值的请求占比。它优于只报均值，因为系统目标是尾部体验；但单独用“达标率”会把 5.01 s 与 50 s 都计为失败，也会隐藏阈值内部的分布。因此论文同时在敏感性图中给 P99 TTFT/P99 TBT，并另报 throughput。

基线共六类：vLLM 0.6.6.post1（V1 engine）、TensorRT-LLM 1.1.0、LightLLM Past-Future scheduler、LTR、NEO、SuperInfer。全部启用 PagedAttention 与 chunked prefill。Pie、HeteGen、Select-N 因当时无公开代码被排除，FlexGen 因缺少 PagedAttention/chunked prefill 被排除，InfiniGen 等有损近似方案也未纳入（§5.2，PDF p.9）。这种选择保持实现可跑，却使“最相关的 GH200 competitor Pie”没有 head-to-head。

8. 逐层消融、超参敏感性与相变

8.1 组件消融

Figure 17（PDF p.10）比较 vLLM、仅 RotaSched + 低传输预算 L（(B_{xfer}=300)）、仅 RotaSched + 强行高预算 H（(B_{xfer}=2400)）、完整 SuperInfer。能稳健推出三点：

  1. RotaSched(L) 已提高 TTFT attainment，说明调度本身有效；
  2. 在低效 transfer engine 上强行把预算提到 2400，会因传输不能被 compute 覆盖而显著伤害 TBT；
  3. 完整 SuperInfer 才能同时用大预算和保持 TBT，证明 RotaSched 与 DuplexKV 是乘法关系，不是两个独立小优化。

Figure 17 仍未印出精确表格，故不填造数值。Table 1 则把 DuplexKV 内部按 Naive → MS → MS+MK → full duplex 分层，表明最大跃迁来自大 segment 与 merged kernel，eager full-duplex 再把 63.14 ms 降到 46.80 ms（绝对 16.34 ms，相对 25.88%）。这提醒读者：论文的“核心新颖性”与“最大性能来源”并不完全同一件事。

8.2 ()：TTFT/TBT 的明确 Pareto

Figure 18（PDF p.10）固定 (_B=_F=0)，扫 ({1,2,3,4,5,10,50,100})。() 越大，rotary 请求越快获得优先级，TBT attainment 上升，但 waiting 请求被延后，TTFT attainment 下降。作者建议 TTFT 敏感场景用 ()，称 () 为平衡点；再增大只有递减的 TBT 收益，却显著损伤 TTFT。主实验因此选 3。

8.3 (_F)、(_B)：阈值相变

Figure 19 固定 (,_B=0)，当 (_F) 时 P99 TTFT 急剧上升而 TBT 改善很小：waiting 请求的 VLT 被容忍窗口压住，直到过晚才获得优先级。Figure 20 固定 (,_F=0)，更大的 (_B) 会延后 rotary 请求恢复、恶化 P99 TBT；作者建议 (_B<0) 获得更好的 TBT tail，代价是 TTFT tail 上升（§5.3.2，PDF pp.10–11）。这不是平滑调参，而是存在清晰的 SLO 相变区。

8.4 (B_{xfer})：硬件能力被显式写入调度

Figure 21 扫 (B_{xfer}{300,600,1200,2400,4800})，更大预算显著降低 P99 TTFT 与 TBT（§5.3.4，PDF p.11）；但曲线未给点值。预算越大，单轮可清理 backlog 越多，也越依赖 DuplexKV。与 Figure 17 合看，结论不是“预算越大越好”，而是“只有传输引擎能覆盖预算时，预算增大才有正收益”。

9. 统计显著性与可复现性

论文未报告多随机种子、重复次数、误差条、置信区间或假设检验；Figure 16–23 均为单条系统曲线。因此可以说在给定 GH200、Poisson 到达、固定 SLO、固定软件版本下观测到大幅差异，不能推出跨机器、跨时段稳定的总体效应。系统实验的主要随机性来自请求采样、Poisson 到达和运行时噪声，恰好需要重复试验；“最大 +74.7 pp”尤其应配 bootstrap 请求级置信区间。

可复现性比许多系统论文更好：官方仓库保留 vLLM fork、C++ swap thread、LVF scheduler、AsyncEngine 服务器、load generator 与 AE_AIO_0309_v1.py，并列出 CUDA 12.4 与单 GH200 配置。仓库 README 同时明确“其他 Ampere/Hopper 卡应可工作但未测试”，这不是跨硬件保证。当前仓库 3930 commits 的大部分来自 vLLM 历史；复现时应锁定分支/commit，而不能把 commit 总数误当项目成熟度。

10. 技术来源链：解决什么—遗留缺口—SuperInfer 如何回应

10.1 PagedAttention / vLLM：从碎片浪费到块式 KV

PagedAttention 把 OS 虚拟内存思想带入 KV 管理，使内存浪费接近零并支持跨请求共享；SOSP 2023 报告在同等延迟下吞吐提高 2–4×。遗留缺口是块式布局优化了容量，却把每个请求的 KV 散成大量小 segment；这恰好让 CPU–GPU 批量传输效率很差。SuperInfer 不否定 paging，而是在 block table 之上加 block-first 传输布局和 merged kernel。设计传递关系是：逻辑分页保留，物理搬运重排。

10.2 Sarathi-Serve：从 prefill 抢占 decode 到 stall-free batching

Sarathi-Serve 用 chunked prefill 与 stall-free schedule 消除长 prefill 对 decode 的干扰；OSDI 2024 报告 Mistral-7B 单 A100 capacity 2.6×、Yi-34B 双 A100 3.7×、Falcon-180B pipeline parallel 5.6×。遗留缺口是它假设请求 KV 都能留在 GPU：当 HBM 被长请求占满，chunked prefill 仍没有位置接纳新请求。SuperInfer 保留 chunked prefill，并用主动轮转腾出 HBM。设计传递关系是：先让 iteration 可组合，再让 residency 可轮转。

10.3 LTR：从 FCFS 到预测式 SJF

LTR 发现精确预测输出长度很难，但相对排序可学；NeurIPS 2024 报告 chatbot latency 最多降低 2.8×、synthetic data throughput 提高 6.5×。遗留缺口有两层：需要离线训练 ranker，且无论队列顺序多聪明，HBM 容量耗尽时仍无法运行。SuperInfer 用在线可观测的“已等待多久 / 最近 token 多久”替代长度预测，并允许把 running 请求真正换出。设计传递关系是：从预测工作量转向直接度量 SLO 欠账。

10.4 NEO：从纯搬运到 CPU–GPU 协同计算

NEO 将一部分 attention 计算和 KV 一起卸载到 CPU，用非对称流水和 load-aware scheduling 增大 batch；论文摘要报告 T4/A10G/H100 吞吐最高分别提高 7.5× / 26% / 14%，更强 CPU 上 A10G 最高 79.3%。遗留缺口是 CPU 进入计算关键路径，硬件不平衡与模型支持更复杂；SuperInfer 的 NEO 基线也不支持 Mixtral-8x7B。SuperInfer 选择“CPU 只做大容量 KV tier”，保持计算在 Hopper 上。设计传递关系是：保留异构流水，但缩小 CPU 职责以降低模型耦合。

10.5 Pie：Superchip 上性能透明的内存池

Pie 最接近 SuperInfer：在 GH200 上利用可预测访问与并发 swapping，摘要报告较 vLLM 吞吐最高 1.9×、延迟 2×、同性能 GPU 内存减少 1.67×，较 FlexGen 吞吐 9.4×。遗留缺口是 Pie 以 capacity / performance transparency 为主，没有把 TTFT 与 TBT 紧迫度写进调度，也没有针对高负载的主动轮转。SuperInfer 把 Pie 的“CPU memory pool”提升为 SLO 可控 execution tier。关键缺憾是论文没有与 Pie 做实测 head-to-head，理由是当时无公开代码（§5.2）。

                         ┌─ Sarathi-Serve：chunked prefill / stall-free batch
PagedAttention：块式 KV ─┤
                         └─ LTR / LightLLM：队列排序与未来内存预测
                                  │
NEO：CPU 参与 attention ───────────┼──> SuperInfer：VLT/LVF 主动轮转
                                  │             + DuplexKV 全双工迁移
Pie：GH200 CPU memory pool ────────┘

演进动力不是单线“更快 kernel”，而是三次边界迁移：先从算子走向 KV 内存管理，再从平均吞吐走向 TTFT/TBT SLO，最后从 PCIe 离散设备走向 CPU–GPU 一体化内存层级。SuperInfer 的转折在于把互连能力变成可调度资源，而不是后端实现细节。

11. 真正贡献、可复用设计与迁移潜力

真正贡献有三层。第一，调度抽象：rotary state 与 VLT 把运行进度、首次响应和连续响应统一成“欠账”；这个抽象可迁移到 SSD KV tier、远端 KV pool、prefill/decode 分离集群。第二，布局—协议共设计：eager 同步把 mutable 尾块和 immutable 完整块分开，从协议层消除 full-duplex race；这个思路适用于 activation offload、checkpoint streaming、embedding cache。第三，物理上界意识：论文用 192+192 GB/s DRAM 上限而非 900 GB/s 宣传值做理想基线，是值得复用的系统评测规范。

迁移不是零成本。AMD MI300A 也是紧耦合 CPU–GPU，但缓存一致性、NUMA、copy engine 与内存带宽结构不同，需重测 segment size 和并发方向；PCIe GPU 无法直接复用大 (B_{xfer})，只能借用 VLT 调度而非 DuplexKV 吞吐；disaggregated serving 可把 rotary 变成跨节点状态，但网络 RTT 和可靠性会进入 VLT。若结合有损 KV 压缩，调度目标还要增加质量损失预算，不能只看时间。

12. 论文自述边界与独立批判

12.1 论文自述 / 可直接定位的边界

  1. 参数不能由 workload 自动预测。 §5.3.2（PDF p.11）明确说只给定性行为，(,_B,_F) 应按应用定制，论文不尝试根据在线 query distribution 建立关联或预测。
  2. 低负载时收益消失。 Introduction（PDF p.2）说明内存充足时 SuperInfer 与 baseline 匹配；其价值来自高压下的 SLO-aware memory management，不是普遍降低每 token kernel latency。
  3. 代码验证范围是单 GH200。 官方 README 写明 AE 配置为单 GH200（144 GB HBM、480 GB DRAM），其他 Ampere/Hopper “应可工作但未测试”；论文虽给 TP=2，但仍是同类 GH200/NVLink 环境。

12.2 独立批判（每点均为“因为 X，所以 Y”）

  1. [外部有效性] 因为全部主实验只在 GH200 NVL2、固定 400 GB offload pool 上完成，所以不能把 74.7 pp 推广到 PCIe、MI300A、CXL memory 或云上异构实例；这些平台的 (B_{xfer}) 可行域不同。
  2. [基线公平性] 因为最相关的 Pie 被以“无公开代码”排除，而 SuperInfer正是在 GH200 CPU-memory pooling 上扩展 SLO 调度，所以现有证据只能证明优于已实现基线集合，不能证明优于当时最接近的 Superchip 方案。
  3. [统计可靠性] 因为 Figure 16–23 没有重复次数、误差条、置信区间或显著性检验，所以最大 +74.7 pp 可能放大压力拐点与运行噪声；至少应对请求级达标率做 bootstrap，并对多次 trace replay 报区间。
  4. [阈值依赖] 因为主实验固定 TTFT=5 s、TBT=100 ms，而 (,_B=0,_F=0.5) 的优劣直接由阈值决定，所以“平衡”不是系统固有性质；若交互式语音要求 TBT<50 ms，排序与相变位置可能重排。
  5. [工作负载真实性] 因为 ShareGPT/LMSYS 请求被 Poisson 到达驱动，而真实服务有 burst、昼夜、优先级、相似前缀与重试相关性，所以不能推出对 production burst 的恢复时间；应增加 self-exciting arrival 与 trace-driven replay。
  6. [贡献归因] 因为 Table 1 中仅把 64 KB segment 合到 4 MB 已将 E2E 从 1556.15 ms 降到 159.87 ms（9.73×），而 full DuplexKV 从 63.14 ms 再降到 46.80 ms（1.35×），所以性能最大来源是布局与批量化，不应把全部收益叙述为全双工或调度创新。
  7. [成本与能效] 因为论文只报 SLO、吞吐和时延，没有 GH200 成本、CPU/DRAM 功耗、每百万 token 能耗或与双 H100 的 TCO，所以不能判断“大 DRAM Superchip + 400 GB KV pool”是否比更多普通 GPU 更经济。
  8. [多租户公平] 因为 LVF 总是优先最大欠账，且论文未报 per-tenant slowdown、starvation 或 Jain fairness，所以高优先级/长生成/频繁恢复的组合可能产生策略性占用；需要把租户权重与最大连续轮转次数显式纳入。

13. 开放挑战：可操作的 head-to-head 实验空白

理论

  • VLT vs. deadline/queueing optimum： 在相同到达 trace、相同 HBM/DRAM 与传输预算下，对比 LVF、EDF、Whittle-index、SRPT-with-estimation；报告两类 SLO violation、worst-case starvation 与 competitive ratio。空白在于现有论文只给经验曲线，没有说明分段 VLT 何时近似最优。
  • 固定参数 vs. 在线控制： 用同一 workload 在 stationary Poisson、Markov burst、自激 Hawkes 三种到达下，对比固定 (,)、bandit controller、MPC；预注册目标为 TTFT/TBT violation 加权和与参数切换开销。
  • 无损 offload vs. 有损 compression： 在相同 HBM+DRAM byte budget 下比较 SuperInfer、KV quantization/eviction、二者组合；除 SLO 外加入 perplexity、任务准确率与输出完全一致率，构建质量—容量—尾延迟三目标前沿。

工程应用

  • SuperInfer vs. Pie： 在同一 GH200、同一 vLLM commit、同一 400 GB host pool 上跑 ShareGPT/LMSYS trace；必须报 TTFT/TBT CDF、吞吐、C2C/DRAM 带宽、CPU 利用、功耗与 30 次重复。这是最关键缺失对比。
  • GH200 vs. MI300A vs. PCIe H200： 固定模型与请求轨迹，分别调优 segment size / (B_{xfer})，比较收益相对各平台物理上界的比例，而非绝对 GB/s。
  • 单租户 vs. 8 租户： 给每租户不同 TTFT/TBT SLO 和权重，对比 LVF 与 weighted-LVF；报告 per-tenant attainment、P99 slowdown 与 starvation count，验证轮转是否可用于生产 QoS。

新兴方向

  • reasoning model 长 CoT： 在 DeepSeek/Qwen reasoning workload 上比较 SuperInfer、SkipKV、两者组合；固定答案准确率与最大输出 token，检验“搬全量 KV”与“抑制冗余生成”是互补还是互相干扰。
  • prefill/decode disaggregation： 把 rotary tier 放在 decode pool、远端 KV server 或 CXL memory，比较本地 GH200；报告网络拥塞下恢复 latency 与 failure recovery，检验 VLT 能否跨节点使用。
  • 代理与多轮共享上下文： 与 ContextPilot/prefix caching head-to-head，固定相同上下文复用率；比较“避免重新 prefill”与“主动轮转”在长会话中的边际收益及缓存污染。

14. 近期工作雷达

以下均来自实际访问的 MLSys 2026 正式页，作为后续跟踪而非本报告的深读对象：

  1. FlashAttention-4：针对 Blackwell 的非对称硬件扩展重做 pipeline，在 B200 上相对 cuDNN 9.13 最高 1.3×、达 1613 TFLOPs/s / 71% utilization；它优化单算子，与 SuperInfer 的 residency/SLO 层互补。
  2. ContextPilot：用 context index、对齐和去重让长上下文 prefill 最多加速 3×且保持推理质量；值得与 rotary/offload 组合评测。
  3. MorphServe：运行时交换量化层并动态改 KV 容量，平均 SLO violation 降 92.45%、P95 TTFT 改善 2.2–3.9×；但引入质量维度，比较时必须等质量。
  4. SkipKV：句级去重与 steering 同时减少存储和生成，最高吞吐 1.7×、序列 1.6× 更短；它改变模型轨迹，不是 SuperInfer 的无损替代。
  5. BatchLLM：全局前缀共享与 throughput-oriented token batching 在离线大批量任务上较 vLLM/SGLang 1.3–10.8×；它提醒 SLO 在线结论不能直接外推到 batch serving。
  6. Optimizing Deployment Configurations for LLM Inference：基于 Meta 近十亿月活的数百万配置搜索经验，强调 phase-specific parallelism、异构硬件和 MoE 架构效应；适合把 SuperInfer 放进更大的部署搜索空间，而非孤立调参。

15. 结论

SuperInfer 最值得读的不是“最高 +74.7 pp”本身，而是它展示了一条严谨的系统共设计路径：先找出标称 C2C 与软件实效的两个数量级落差，再用数据布局把 16 GB 双向 KV 迁移从 1556.15 ms 压到 46.80 ms，最后把这项带宽能力通过 VLT/LVF 转换成 TTFT/TBT 的主动轮转。它的证据足以支持“在 GH200、固定 SLO、高负载下显著缓解 HOL blocking”，却不足以支持“普适最优 LLM serving”：最相关 Pie 未实测、主图没有数值表、没有统计区间、硬件与 workload 外推都很窄。对实践者，最可复用的判断是：只有当传输近物理上界且能被计算覆盖时，主动轮转才是调度；否则只是把 HOL blocking 从 waiting queue 搬到 swap queue。
